# packages/ · 模块骨架

> 归属说明，**当前没有代码**。骨架已定（决策 D01），实现随首个验证方案立项开始。

四个可独立使用的模块 + 一个入口包，按调研 §5.3 的"扫描 / 确认 / 缩减 / 回放分离"划分：

| 包 | 职责 | 关键约束 |
|---|---|---|
| `core` | 在声明的压力条件下采集几何与遮挡**候选** | 只产候选，不写判定（I1） |
| `confirm` | 用真实命中测试判定关键操作可达性，产出三态判定 | 禁止用程序化点击当"点得到"的证据（I2） |
| `reduce` | 逐条去掉条件，每去掉一次仍要复现 | 保持失败才算缩减完成（I9） |
| `replay` | 重放既有记录 | 不新增真实外部副作用（I5） |
| `cli` | 可读报告 + 结构化结果，接进现有测试脚本 | 核心能力完整开源（I10）；默认只读 |

约定（建包时同时生效）：

- 包名 `@layress/<name>`；与 npm 上的 `layrr`／`layerr` 无关，README 要显式区分。
- **任何包不得默认写到数据根之外**（I12）：`os.tmpdir()`、Electron `userData`、Chromium `sessionData`
  都要显式覆盖，洁净度门禁会对产品代码里的这类形态判红。
- 包内不写机器绝对路径；产物内路径一律相对数据根 + posix 分隔符。
- 人类可读输出属于产品字符串层，`zh-CN` 默认、`en-US` 待建（口径见 [`/i18n/README.md`](../i18n/README.md)）。
- 纯 TS 库不依赖 Electron；Electron 相关只出现在 `apps/desktop`。
