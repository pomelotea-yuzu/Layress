# datasets/ · 正负例数据集

> 归属说明。调研 §5.4 把这个目录列为**最有积累价值的资产**——比规则数量、截图包装或多加模型调用都值钱。
> 因此它的规矩比代码还严：进来的每一条样本都要能说明它证明了什么。

## 目录结构（首个 change 建实际内容）

```
datasets/
├─ cases/
│  ├─ tuning/     调规则用：可以反复看、用来改判定阈值
│  └─ eval/       最终评估用：不参与规则迭代（不变量 I7）
├─ negatives/     看起来坏但没问题的样本
└─ README.md      本文件 + 每个子集的来源与授权记录
```

`tuning/` 与 `eval/` **物理分离**不是洁癖：同一批页面既用来调阈值又用来报精确率，指标会随规则一路上涨，
而外部项目一个缺陷都发现不了——首验结论直接作废（I7）。

## 每条样本必须带的字段

缺任一项就不算"可回放证据"，也不许进评估集（不变量 I3、I4）：

- 尺寸：内容区宽 × 高（CSS px）
- 界面状态：侧栏展开 / 标签激活 / 错误提示出现等
- 字体与缩放：系统字体、浏览器缩放、DPR
- 语言 Locale
- 目标元素与（若有）遮挡元素
- 期望判定：`confirmed` / `not-a-defect` / `inconclusive`
- 来源：项目、提交或版本；真实历史缺陷的 issue/commit 引用

## 样本来源纪律

- **真实历史缺陷优先**，人工注入缺陷只作补充，**不替代**真实案例（调研 §7.3）。
- 负例要专门收集：合理省略（ellipsis）、滚动区域、抽屉菜单、浮层、可折叠工具栏——
  这些是"看起来坏但其实没问题"的典型，缺它们就无法证明误报率低。
- 至少一半来自**外部项目**（调研 §7.3）：自己的案例适合起步，不足以证明通用性。
- 数据集规模建议 5–8 个真实项目、约 30–50 个页面状态。

## 入库与授权（重要）

- 页面内容、截图与被扫描应用的数据默认不出本机（I8）。进本目录前必须确认**可公开**：
  开源项目的页面样本需要核查再分发许可与署名口径——**未核**，见
  [`docs/knowledge/debt.md`](../docs/knowledge/debt.md)。
- 含姓名、地址、内部路径、业务标识的样本一律脱敏或改为最小合成页面。
- 大文件与归档一律走 [`.git-hygiene-allowlist`](../.git-hygiene-allowlist) 登记 `glob + 理由`，
  无理由判红；能用生成脚本复现的页面结构**优先提交生成器**，不提交产物。
- `.gitattributes` 已把 `datasets/**` 标为 `-text`：内容按字节稳定，行尾不许被改写（改了回放对不上）。

## 与代码的关系

数据集不是测试夹具的替代品：`tuning/` 允许用于开发期观察，`eval/` 只在评估轮使用；
调参过程中**不许读** `eval/` 的结果来改规则。这条要在测试代码里可核验，而不是靠自觉。
