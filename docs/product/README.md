# docs/product/ · 方向与路线

> 归属说明。这里放**长期有效的产品口径**：定位、能力边界、路线图、商业化判断。
> 不要求中英成对。

## 这里放什么

- `product.md`：定位句、目标用户、JTBD、护城河、产品化缺口
- `roadmap.md`：能力阶段与发行节点，每个节点写清**证据门槛**（不是日期承诺）
- 决策纪要：一次讨论定下一个口径时，结论写这里，过程留在 change 的 design.md

## 纪律

- 与 [`../../AGENTS.md`](../../AGENTS.md) §一 和不变量保持一致；口径变了要同轮改不变量表。
- **路线图只写"准备做"，不写"已做到"**：已完成的事实进 `openspec/changes/archive/` 与 `CHANGELOG.md`。
  前置项目的产品文档就吃过"路线图停在旧日期"的亏。
- 暂缓项（审美评分、自动修复、全平台矩阵、最小 HTML 抽取）明确列出，防止被当作遗漏重开。
