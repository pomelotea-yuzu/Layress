## 目标与阶段边界

第一阶段验证一次完整体验：选择页面与设备 → 操作到问题现场 → 记录画面 → 圈画并写短描述 → 保存后再次查看。
Agent 领取任务、回传处理结果与修复后复核属于第二阶段；本阶段保存的反馈需要保留可继续关联的现场。
首轮普通页面是验证样例，不把某个页面、框架或桌面视口变成产品永久定位。

## 三个容易混淆的概念

| 概念 | 用户看见什么 | 需要验证什么 |
|---|---|---|
| 独立浏览器窗口 | 一个窗口是 Layress 工作台，另一个窗口是正常打开的被测页面 | 启动、页面与窗口对应、采集入口是否顺手；新会话不自动继承日常浏览器登录状态 |
| 页面内悬浮工具 | 被测页面旁有小按钮，展开后可记录现场、标记或返回工作台 | 注入 / 扩展 / 项目接入方式、遮挡与事件冲突、工具层是否污染截图 |
| 工作台内展示页面 | 在 Layress 内看到被测页面或其画面 | iframe 与浏览器画面转发的限制不同；嵌入后不能假定能读取任意页面 DOM |

独立浏览器与悬浮工具可以组合：页面在独立窗口运行，同时带一个轻量工具入口。
悬浮按钮本身不赋予整机鼠标控制能力；具体可操作范围取决于浏览器、扩展或桌面接入实现。
上述为形态比较，后续用户反馈已否定把双窗口与手动搬运作为主体验的建议。当前优先验证单应用主窗口内操作页面的方案，不以普通 iframe 作为可靠接入假设。

## 单应用体验与差异化待验证项

- 主窗口集中承载被测页面、设备配置、原地批注和记录入口；设备选择直接控制实际视口，无需用户拖动主窗口凑尺寸。
- 画面显示缩放与被测页面实际视口分开；工具面板展开不应悄悄改变本次设备配置，具体布局需要原型验证。
- 标记时自动采集，原地输入描述并保存；不要求用户手工截图、找文件和到另一窗口补上下文。
- 小而美指向启动、操作与退出顺手，工具按需展开；不把大量工具同时堆到主界面。Electron 包体积、会话与渲染范围仍需实测。
- 单应用、多设备、圈画、Agent 往返与截图差异都有现有产品先例，不能仅凭组合就声称独特；见[本轮同类产品核查](../research/2026-11-10-integrated-review-differentiation.md)。
- 下一步围绕一个具体任务比较：一次指出问题后，能否保存必要条件、在修复后减少重新准备与复述，并清楚呈现检查覆盖范围；这是候选价值，尚未验证优于现有工具。

## 页面与设备的基础流程

以下为建议交互，尚未逐项确认：

1. 选择或新建项目，选择最近页面或输入 URL；同一项目允许切换路由 / 页面，不仅限首页。
2. 选择桌面、平板、手机或自定义预设，按需调整视口与横竖屏；显示浏览器及模拟 / 真机类型。
3. 在开始前恢复该项目上次使用的页面与设备配置，允许修改；建议按项目记忆，避免不同项目互相覆盖。
4. 打开页面并正常操作至需要的状态；切换设备配置时提示是否需要重新加载，不能默默丢失表单或登录现场。
5. 记录现场，基于固定截图圈画并输入原话；建议首轮提供框选、箭头、撤销与删除。
6. 保存并可重新打开反馈。采集失败明确报错；页面继续变化时，已保存现场保持原样。

设备预设并非只有宽高：实现时根据接入能力处理 DPR、触摸、UA / 移动模式等，不能修改预设名称后仍偷偷沿用桌面配置。
浏览器模拟只代表声明的模拟条件；无法证明真实手机的 Safari / WebView、软键盘、安全区域或性能已经通过。
手机真机接入方式和首批支持范围后续按需求验证，不作为本阶段默认交付承诺。

记忆的配置用于下一次开始；每条现场独立保留当次实际 URL、时间、视口、截图尺寸、滚动状态、设备模拟条件及可取得的信息。
日后修改默认配置不能改写旧反馈。为以后复查保留条件，不代表可以自动恢复全部业务状态。
产品不应为记住选择而默认保存真实账号密码或表单内容。

## 模型鼠标控制能力的影响与准备

以下为产品与架构判断，**不是当前模型横向测评或能力普及率统计**。

- 当 Agent 越来越擅长打开页面、点击与截图，单独提供这些能力的差异会减弱；应持续验证圈画反馈、上下文交接、设备条件和修复前后复查能否减少实际来回。
- 操作能力增强也可作为执行来源：人工操作、现有浏览器自动化与未来模型操作都应能关联同一反馈与现场，不让任务事实绑定某个模型。
- 先围绕同一浏览器会话的采集条件和现场建模；具体适配器在出现实际接入时增加，不提前自建通用桌面控制器或模型平台。
- 保留画面坐标、原图尺寸、视口、DPR、滚动与时间等信息，供视觉和 DOM 操作按各自可用证据定位；页面变化后坐标必须重新确认，截图不能当永远有效的动作目标。
- 人和 Agent 操作同一会话时需要明确控制权和停止入口；异步执行需记录具体动作与结果。能力接口与授权范围分开，不因模型能点击就放开整机操作。
- 继续提供可发现的 CLI 与结构化事实，让具备工具调用的 Agent 直接取得证据；视觉 / 鼠标操作是可选接入，不能强迫 Agent 点击工作台按钮完成所有事情。
- 远程视觉模型会收到页面截图，沿用产品已确认的数据流与授权要求，不默认新增模型调用与费用。

## 原型交付与验收建议

建议交付一套可体验的本地原型、一个普通页面样例，以及明确的接入与支持限制说明；不以静态界面稿替代接入验证。

| 场景 | 应能确认的结果 |
|---|---|
| 首次选择页面与设备 | 能操作到目标页面、滚动或打开弹窗，并记录当次画面 |
| 再次打开工作台 | 恢复上次配置，允许修改；不自动触发页面业务操作 |
| 切换设备 | 实际采集配置与所选条件一致；旧现场保持原样 |
| 圈画与工作台缩放 | 框选 / 箭头仍对应原图位置，不随显示缩放偏移 |
| 保存、刷新与重新打开 | 原图、标记与原话仍可查看；同一反馈内容不丢失 |
| 页面更新或采集失败 | 新旧现场分开；失败不显示为本次采集成功 |
| 数据保存 | 解析后的数据目录可见，浏览器运行数据也留在约定数据根 |

以上均为待执行项，没有机器或人工通过记录。框架、具体浏览器库与包划分在进入实现时按实际依赖与许可确定。

## 接下来讨论

- 单应用主窗口的操作、批注与复查布局，以及 Electron 能否以可接受体积承载；独立双窗口不再是推荐的主体验。
- 一个真实任务上，相比现有工具或组合实际减少哪些步骤；不以增加工具数量代替差异化。
- 设备预设及自定义范围、配置按项目恢复的具体方式。
- 本阶段首轮浏览器模拟范围，以及何时需要手机真机接入。

讨论结果确认后再形成对应实现 change；本文不构成已选定浏览器、扩展、桌面壳或模型的技术决策。
