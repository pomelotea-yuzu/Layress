> 用户明确要求从 Electron 候选转为 Tauri（D25），本计划已同步；具体版本、WebView 承载 / 采集方案与包划分留待实现设计，本轮仅改文档。
> 同日后续：用户要求建立首个 change，已落为 [add-tauri-page-host](../../openspec/changes/archive/2026-11-14-add-tauri-page-host/proposal.md)。本轮只建立首增量文档，未开始编码；其余阶段范围仍按本提案逐步确定。

## 阶段目标

交付一个可以在日常开发中尝试使用的本地应用：**一个主窗口内打开网页、选择设备、操作页面、原地记录问题，并在修改后手动补拍查看**。
省去手动拖窗口凑尺寸、截图找文件、切换到另一个工作台重新描述的步骤。
首阶段负责把人的操作与现场记录做顺；完整的人和 Agent 任务闭环在第二阶段接上。

本提案建议在原阶段 1 范围上增加“同一反馈下手动补拍、前后查看”，用于观察记录是否能服务修改后的检查。
它只复用设备与页面配置，业务状态仍由用户操作准备；自动恢复操作、Agent 自动领取和自动验收不计入本阶段。
这是一项待审阅的范围补充，不宣称已经建立差异化或实现了可重复自动验收。

## 主窗口形态

```text
┌─────────────────────────────────────────────────────────┐
│ 项目 / 最近页面  地址  后退 / 前进 / 刷新     记录问题     │
├─────────────────────────────────────────────────────────┤
│ 桌面 / 平板 / 手机 / 自定义   宽高   横竖屏   适应窗口    │
├───────────────────────────────────────┬─────────────────┤
│                                       │ 反馈 / 详情面板 │
│             被测网页画面              │ 按需展开        │
│        点击、输入、滚动、打开弹窗      │ 原话、现场记录  │
│                                       │ 前后查看        │
├───────────────────────────────────────┴─────────────────┤
│ 当前配置与状态                  本地数据位置 / 设置入口  │
└─────────────────────────────────────────────────────────┘
```

页面占据主要空间；项目与反馈管理通过可收起面板进入，不常驻大型仪表盘。
默认一个活动页面，可切换 URL 与路由；多项目与反馈保留记录，多标签和多视口并排留后续按需增加。
“一个活动页面”是首阶段实现范围，不是产品只服务单页应用的定位。

选择设备控制被测页面的**实际视口**；适应窗口只改变画面的展示比例。
展开工具面板或调整应用窗口不应悄悄改变已选择的设备宽高；尺寸放不下时提供缩放或平移，标记仍对应原图。
进入标记模式时先采集当前画面，再在同一画面区域显示静态批注；退出后继续原页面会话。
记录现场不代表冻结页面脚本、网络请求或服务器状态，不向用户承诺业务状态被暂停。

## 功能范围与实际流程

| 模块 | 第一阶段交付建议 | 对用户的作用 |
|---|---|---|
| 项目与页面 | 项目名称、起始地址、最近页面、项目切换；使用已运行的开发服务 | 无需每次重填地址，不要求先关联源码目录 |
| 浏览操作 | 内置页面、地址导航、前进后退、刷新、加载 / 失败提示、基本输入与滚动 | 在应用内把问题操作出来 |
| 设备配置 | 通用桌面 / 平板 / 手机预设、自定义宽高、横竖屏；按项目保存上次选择 | 无需手动调整窗口得到目标尺寸 |
| 原地反馈 | 记录当前视口、框选、箭头、撤销 / 删除、短描述、取消与保存 | 无需手动截图、找文件和另开描述窗口 |
| 记录管理 | 项目内反馈列表、原图 / 标记 / 原话、补充说明、删除确认、关闭重开后恢复 | 一条问题可以持续补充和查看 |
| 手动再次查看 | 从反馈恢复地址与设备配置，人工准备状态后补拍；同一问题查看前后现场 | 修改后少重新设置条件，保留原始记录 |
| 反馈摘要 | 复制带反馈标识、原话、条件与本地证据引用的文本；图片可在应用中查看并按需导出 | 第二阶段接入前可手动交给已有 Agent，不声称已自动发送 |
| 本地运行 | 可见数据目录、启动 / 保存 / 采集失败提示、正常退出和再次启动 | 数据留本地，失败原因能理解 |

一次使用示例：打开项目 → 恢复上次手机配置 → 操作到编辑弹窗 → 点“记录问题” → 框住保存按钮并写一句话 → 保存后继续浏览。
修改后打开该反馈 → 选择“按原条件打开” → 人工重现弹窗 → 补拍 → 在同一反馈里查看前后画面。
重新打开页面只恢复明确支持的条件；登录、表单、临时数据和复杂流程不会被暗示为已经自动恢复。

手机与平板预设明确标为浏览器模拟。实现时核查实际宽高、DPR、触摸与移动模式等，不只替换预设名称。
Tauri 系统 WebView 未必支持相同的模拟项，界面按实际能力区分“视口预设”与其他模拟，未实现项明确显示；不能把改宽高当完整手机模拟。
不以系统 WebView 或 UA 修改声称真实 iOS Safari、Android WebView、软键盘或性能已经验证；真机和多引擎接入后续按需验证。
设备切换若需要重载，先提示用户；按项目恢复配置，不在启动时自动提交表单或执行页面业务动作。

## 现场与后续衔接

每条反馈有稳定标识，现场有独立标识；保存原图、标记、原话、采集时间、实际 URL、视口、画面尺寸、滚动状态和可取得的设备条件。
必要复现说明允许用户补充，不强制填写正式用例；DOM 信息可取得时附上，第一阶段不以可靠源码映射作为前提。
原图与新现场分开保存；修改设备默认值或补拍不能覆盖旧反馈。补拍画面不自动复用旧标记，也不自动判定修复成功。
界面和后续 CLI 围绕同一份有版本的本地事实组织，不把反馈仅存在某个界面组件里。
本阶段不承诺外部接口名、状态机或自动接入的 Agent 客户端；机器读取和处理结果回传在第二阶段实现。

## 实施顺序与交付物

以下顺序按可体验增量推进，每步尽早使用上一增量，不先铺完所有工程设施。

| 顺序 | 做什么 | 本步可审阅的结果 |
|---|---|---|
| 1 · 窗口与页面承载 | 定主窗口操作，建立最小 Tauri 工程与公共检查；验证系统 WebView 内页面导航、输入、弹窗、固定视口、截图与原地批注叠层 | 一版能打开真实页面、切换视口并采集干净画面的骨架；记录实际引擎、窗口、焦点与模拟限制 |
| 2 · 项目与设备 | 项目 / 地址记录、三类通用设备与自定义、横竖屏、显示缩放、配置恢复 | 关闭重开后，继续使用项目上次的页面与设备；不靠手动拖窗口准备尺寸 |
| 3 · 原地批注 | 捕获后显示同位置静态批注、框选 / 箭头、短描述与保存 | 在表单或设置页上实际指出问题，应用自动整理画面和条件 |
| 4 · 记录与手动补拍 | 反馈列表、详情、补充说明、按原条件打开、补拍与前后查看、复制摘要 | 同一问题从发现到修改后查看可一直使用同一条记录 |
| 5 · 日常试用与收尾 | 换普通真实项目试用，处理失败 / 恢复、检查便携存储、生成本机可运行包并记录体积 | 可试用应用、简短上手与限制说明、包体积 / 资源观测和逐项验收记录 |

首个增量已建立 [add-tauri-page-host](../../openspec/changes/archive/2026-11-14-add-tauri-page-host/proposal.md)，技术方案、任务和证据计划留在该 change（**2026-11-14 已实施完成并归档，规格合入主规格**）；后续增量按实际范围另立 change。
工程采用 Tauri 的 Rust 原生层与 TypeScript strict 前端，前端使用 pnpm；具体版本、UI 框架、任务核心与 CLI 的语言边界由实现设计确定，不预设仅用 Node.js 的核心或另一套重复任务记录。
新增 Rust / 前端构建、类型和必要行为测试接入现有公共门禁，保持本地与 CI 同链；视觉、焦点和交互另做人工复核。本轮不安装 Rust / Tauri 或产品依赖。

## 首轮验证范围与约束

- 开发与首轮实机验证建议先在现有 macOS arm64 环境完成，交付本机可运行应用；Windows / Linux 保持可移植设计，未实测不声明通过，也不沿用旧三端发行承诺。
- 首轮以普通 Web 页面验证点击、输入、滚动、路由和页面内弹窗，再换一个真实项目检查可复用性；复杂登录 / 新窗口等按实测公布限制，不要求先重做浏览器全部功能。
- 默认依托系统 WebView：Windows 为 WebView2、macOS 为 WKWebView、Linux 为 WebKitGTK，能力与版本随平台变化。先验证本机页面承载、隔离、视口、截图与批注，不假定拥有 Electron / CDP 的全部接口。
- 默认不附带另一套 Chromium 或 Node.js。若实现需要外部执行引擎，记录用途、接入方式、总下载 / 安装体积及便携存储影响，作为明确方案调整讨论，不静默换回 Electron 或退成双窗口手工搬运。
- 被测页面与工具界面分离权限，不能让外部网页调用 Tauri 原生命令、读取任意本机文件或启动进程；页面加载失败不影响已保存反馈。
- 数据、日志、缓存、WebView 会话及临时资料遵守便携数据根；逐端核查 Tauri / WebView 默认路径，目录不可写明确报错，不回落系统用户目录，不默认读取日常浏览器的登录会话。
- 本阶段不新增远程模型调用，不自动上传页面或反馈；复制 / 导出由用户主动操作，本地图片路径也可能包含敏感信息。
- 包体积是收尾必须测量的项目：记录压缩包、解压后大小、系统 WebView 前置依赖是否已有或另需下载、是否附带额外浏览器及内存观测条件；不将应用小包体积直接当成完整安装成本，不承诺未经验证的 MB 数字。

## 阶段完成标准

以下项目全部为**待执行**；机器检查通过与人工体验结论分别记录。

| 验收场景 | 通过应看到什么 |
|---|---|
| 单窗口主流程 | 在一个主窗口内完成页面操作、记录、圈画、说明和保存，无需手工截图或切到另一个工作台 |
| 设备条件与窗口大小 | 实际视口与所选配置一致；实际 WebView 引擎、已启用与未实现的模拟项可见；展开面板、展示缩放和调整窗口后仍能解释当前条件 |
| 重新启动 | 项目、最近地址、设备配置与已保存反馈可恢复；不把配置恢复说成完整业务状态恢复 |
| 标记位置 | 在不同展示缩放与实测 DPR 下，框选 / 箭头仍对应原始画面；截图不含工具层 |
| 修改后补拍 | 同一反馈保留原始现场与新现场，条件差异可见；未检查或仅采集不显示为已通过 |
| 失败与取消 | 地址不可达、采集失败、保存失败和取消均有明确反馈，旧记录可继续查看，不伪造本次成功 |
| 数据与退出 | 数据目录可见、资料留约定位置，退出后本次应用资源释放；新建反馈不会因正常重启丢失 |
| 真实使用 | 在一个日常样例和另一个普通项目中使用，记录相比手工流程省下的动作、剩余阻碍与人工结论 |
| 可交付性 | 有本机可运行包、实际体积、最短上手和已验证支持范围，未做的平台与功能单列 |

这些结果用于决定下一增量如何改进，不恢复“先证明市场空白 / Agent 必败才能开工”的旧闸门。

## 与后续阶段的边界

第二阶段负责 Agent 非交互读取任务、回传结果、人和 Agent 往返与明确的复核流程；本阶段的复制摘要只是可用退路。
第三阶段负责可重复执行的验收任务与必要准备；本阶段按原配置打开并手动补拍，不等同自动回放或自动验收。
多设备并排与同步操作、通用操作录制回放、AI 自主探索、整机鼠标控制、审美评分、全套检测规则、真机矩阵、MCP 和公开多平台发行均不列为本阶段完成条件。
上述内容是分期安排，后续由真实需求调整；本阶段的价值是可连续使用的单窗口体验与可靠现场，为后续闭环提供基础。

## 技术依据与核查边界

2026-11-10 已读取 [Tauri 架构](https://v2.tauri.app/concept/architecture/)与[WebView 版本说明](https://v2.tauri.app/reference/webview-versions/)：Tauri 复用系统 WebView，平台引擎不同；[Electron 简介](https://www.electronjs.org/docs/latest/)明确其随应用嵌入 Chromium 与 Node.js。
以上仅支持架构差异，本项目尚未做 Tauri 功能探针、体积测量或平台写盘验证；Tauri 已选定不等于这些能力已通过。
