> This records "what was decided / why / at what cost / under what condition it would be overturned".
> **Look settled matters up here instead of reopening the debate inside documents.**
> Old entries overturned by a later decision stay in the `design.md` under `openspec/changes/archive/`;
> this table keeps only the current policy.

| # | Decision | Rationale | Cost | Overturn condition |
|---|---|---|---|---|
| D01 | pnpm monorepo: `packages/<core\|confirm\|reduce\|replay\|cli>` + `apps/desktop` | Survey §5.3 requires the four modules to be usable independently; desktop adaptation is deferred but its slot must be reserved, otherwise a single package has to be split apart later | The directories sit empty in the early phase and there is one extra workspace configuration layer | First validation shows the four modules cannot be decoupled (for instance all logic has to share one in-page probe runtime) |
| D02 | Bilingual docs use **same-directory `*.en.md`**, with Chinese as the source; no `en/` subtree | Both copies appear in the same diff, so a missed one-sided edit is visible; an `en/` subtree would mean maintaining relative links and the directory map twice over | The file count per directory doubles; the gate has to exist or this rots | More than three languages appear (at that point locale subtrees are cheaper) |
| D03 | The knowledge base is **committed** (`docs/knowledge/`), not kept in a local memory directory | Item 3 demands it: any developer or any agent can pick the work up after cloning. 90% of the sibling project's experience was blocked outside the repository by `.gitignore` | Pitfall entries must state "verified / not verified" and cannot be scribbled like a local memory log | None |
| D04 | Cleanliness uses a **deny-by-default script plus auditable exemptions**; `.gitignore` is only the backstop | An ignore list allows by default — one `add -f` writes hundreds of MB into a history that can never be erased; an exemption has to carry a reason to leave an audit trail | Every clone must run `git config core.hooksPath .githooks` once; CI gains one more step | None |
| D05 | Only two dump sites are allowed: `artifacts/` (rerunnable output) and `.layress/` (runtime data and logs) | The sibling project's `output/` rotted through "toss it here for now" and ended up needing comments to explain its historical moves. Fewer names leaves no room for a third choice | Deciding where something belongs has to happen before tossing it | None |
| D06 | Adopt the openspec three-part layout (`config.yaml` + `specs/` + `changes/{,archive/}`) | Decisions need a fixed container, otherwise the authority order cannot stand (source code > archive > specs > docs > index) | Depends on the openspec CLI and on workflow habits | Changes stay smaller than 3 steps over the long run, so the process cost exceeds the benefit |
| D07 | Forms are **not duplicated**: GitHub issue/PR forms carry both languages side by side, the Gitee side is pure Chinese | Two forms leave submitters unsure which one to fill and nowhere to compare whether the wording is equivalent | The wording in the three places must be aligned by hand in the same round (the script does not check semantic equivalence) | The overseas contribution share rises until the Chinese side-by-side becomes noise |
| D08 | License is MIT | Consistent with the author's existing open-source projects, dependency license compatibility is easiest to check, and ecosystem acceptance is the highest | No explicit patent grant clause | A commercialization path emerges that needs patent terms, or a dependency introduces a GPL conflict |
| D09 | GitHub + Gitee dual-track CI configuration is in place (`.github/workflows/ci.yml` and `.workflow/ci.yml` run the same chain) | Mainland network access and exposure channels; inconsistent commands on the two sides produce "green locally, red on one side" | Two CI definitions that have to be maintained in step | A single remote already suffices and the mirror goes unused |
| D10 | First release shape = **CLI + readable report + structured results**, allowed to be wired into existing test scripts; the desktop UI comes later | Survey §5.3; make the reliability of detection / reduction / replay solid first, UI is packaging | There is no demoable interface early on, so spread relies on text and screenshots | First validation finds that users must have interactivity in order to confirm a verdict |
| D11 | Brand name `Layress`; distribution via the scoped packages `@layress/*` | Product/GitHub/npm/`.com` were all unclaimed (survey §5.5); `layrr`/`layerr`/`layui` share the prefix and are easy to confuse | Scoped package names require an npm organization; the README must distinguish near names explicitly | `layress.com` registration fails and search confusion is measurably severe |
| D12 | Language policy: output defaults to Chinese while the product name stays English; internationalization = China users first + the capability to publish overseas | The target users and the accumulated value both sit on the Chinese side; the structure is prepared up front — switching target users is not what internationalization means | Front-door documents need both languages in the same round, so writing slows down | None |
| D13 | Right now this repository **builds only structure, index and gates**: no dependencies installed, no business code | The first-validation plan is not approved yet (survey §7); writing code first would produce a skeleton that has to be overturned | For the moment the gates are only the two real commands, cleanliness and bilingual pairing | The first-validation plan is approved — move straight into the workspace skeleton |
