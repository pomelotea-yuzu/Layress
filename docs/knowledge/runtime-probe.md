# runtime-probe.md · 实机探针硬事实

> 本文默认以中文维护。

> 条目格式见 [`README.md`](README.md)。**标注"来源：前置项目"的条目未在 Layress 复核**，
> 按现象假设处理可以，当成本仓已验证事实不行——Layress 的探针栈还没选。
> 这类坑的共同特征：**探针红不等于产品红，探针绿不等于产品对**。

## 通道与时序

- [2026-11-03][P0] CDP `Runtime.evaluate` 返回对象时，调用方拿到异常或被吞掉的结果 ⇒ 求值通道的返回体必须是可序列化基本类型 ⇒ 探针一律 `return JSON.stringify(...)`，取字段判据则明确返回对象并逐字段断言 ⇒ 来源：前置项目三批探针实证。
- [2026-11-03][P0] 探针"看似正常"但目标控件永远查不到 ⇒ 端口被上一轮孤儿 dev host 占走，新起的 dev 静默换了端口，CDP 连的是旧实例 ⇒ 探针前必须显式停掉并确认端口归属，探针结尾 `process.exit()`，禁止留尾 ⇒ 来源：前置项目。
- [2026-11-03][P1] 后台任务里起的浏览器/Electron 在探针读取前就被回收 ⇒ "start→probe→stop" 必须写在同一次调用的链式命令里，跨调用实例已消失 ⇒ 来源：前置项目。
- [2026-11-03][P1] 懒加载编辑器/图表取值偶尔 undefined ⇒ 首屏不挂载，时序敏感 ⇒ 所有取值改为轮询带超时，不用固定 sleep；固定 sleep 在慢机上必红。

## 输入与焦点

- [2026-11-03][P0] 程序化 `.click()` 通过，真实指针点击被拦截 ⇒ `modal`/top-layer 与遮挡层只作用于真实命中测试，程序化点击绕过了本产品要测的那件事 ⇒ **可达性判定必须走真实坐标的 `dispatchMouseEvent`**，程序化点击只用于准备状态。这是产品级不变量，不是探针偏好。
- [2026-11-03][P1] 真键盘注入时好时坏，且焦点归属看起来没错 ⇒ 通道对前台窗口归属敏感，别的窗口抢焦点即游走 ⇒ 每批按键前显式预放焦点并在指令里指到物理控件；复跑恢复≠随机噪声。来源：前置项目。
- [2026-11-03][P1] `insertText` 丢首字符或写进错控件 ⇒ 未先 focus；`Tab` 穿透富文本编辑器改变选区；`Enter` 注入带 `\r` ⇒ 键盘采集三条分开处理，测前断言目标已聚焦。来源：前置项目。
- [2026-11-03][P1] 输入法（IME）组合态下文本注入与最终提交内容不一致 ⇒ 中文/日文输入走合成事件；判据只读提交后的值 ⇒ 语言切换类压力条件必须覆盖 IME 路径，否则测的是英文场景。
- [2026-11-03][P1] 控件报"已聚焦/已选中"但界面实际没变 ⇒ 遮罩层吞 focus 后仍更新了状态，判据假绿 ⇒ 写操作前断言无 `[open]` 对话框；状态判据与视觉判据成对出现。来源：前置项目。

## 几何与视口

- [2026-11-03][P0] 同一条"窄窗口"缺陷在不同机器上复现宽度差十几 px ⇒ 默认窗口宽度正好骑在 CSS 断点线上（前置项目实测 1360 物理宽 ≈ 963 CSS px）⇒ 压力条件必须记录**内容区 CSS px**、DPR、缩放三者，并前置显式改窗到已知档位 ⇒ 来源：前置项目；Layress 首验必须自测这条。
- [2026-11-03][P1] 宽度区间能记下但换机不复现 ⇒ 只记宽度不记高度/状态/字体/缩放，遮挡条件是联合的 ⇒ 触发条件按四元组存：尺寸(宽×高) + 状态 + 字体缩放 + 语言。缺一项就不算可回放。
- [2026-11-03][P1] DPR=1 与 DPR=2 下同一元素边界不同 ⇒ 物理/逻辑像素换算与 1px 描边取整 ⇒ 判定阈值用 CSS px，记录时同时存 DPR；缩放 200% 单独跑一批。来源：前置项目。
- [2026-11-03][P1] 截图比对在改窗后拿旧帧 ⇒ 帧提交异步 ⇒ 抓取前等一次 rAF + 稳定检测，别信 `wait: 500ms`。
- [2026-11-11][P2] 单窗口多 WebView 用「工具层铺满底层 + 被测层上层覆盖」叠层布局，出现样例页首行文字被工具条穿过、宽高输入被盖住 ⇒ 叠层对边界误差零容忍：条带 CSS 内容高度（约 110px）超过给页面预留的 TOOLBAR_H（88px），且两块 WebView 的坐标解释存在差异空间（auto_resize 与显式 bounds 混用）⇒ 双 WebView 区域一律**显式互不重叠**（工具条 `[0, TOOLBAR_H]`、页面 `[TOOLBAR_H, 窗口底]`，窗口 Resized 时两块都显式 set_bounds），条带 CSS 高度与 Rust 常量严格一致并 `overflow: hidden`，不用叠层 + 透明拼接 ⇒ 证据：用户复验反馈（2026-11-11），改互不重叠布局后重编译启动正常。

## 判据与假绿

- [2026-11-03][P0] 断言恒真 ⇒ 期望值是被测实现派生出来的（同源），或断言参数被工具链吞成空串（非 ASCII 字面量） ⇒ 判据必须能反证：注入已知坏样本必须红；断言参数写 `\uXXXX` 转义并自测转义生效 ⇒ 见 [`engineering.md`](engineering.md) 同条。
- [2026-11-03][P1] 探针红 ⇒ 先分诊再报缺陷：快照旧值 / 选择器漂移 / 夹具 run id 变化都可能让探针读不到，而产品是好的 ⇒ 报告里"探针故障"与"候选缺陷"分开登记，前者进本文件，后者进数据集。
- [2026-11-03][P1] 视觉/交互判定被机器判 PASS 后直接勾完成 ⇒ 视觉正确性归人工复核 ⇒ 未执行的复核单列"未执行"，不写进已交付；机器计数不等于验收。
- [2026-11-07][P1] 用弹窗内的"取消"按钮验证 top-layer 假绿，结果必然是真绿 ⇒ 该按钮本身就在 `showModal` 的 top layer 内，真实坐标与程序化点击都能命中；被遮住的是背景控件 ⇒ 坏样本必须选**被模态遮住的背景同名控件**，或先证明目标按钮真的溢出/不可达 ⇒ 证据：2026-11-07 基线试用（对象细节留本地草稿；独立复现 641 CSS 下 Cancel 中心 `elementFromPoint` 命中按钮，背景同名 Cancel 命中 `DIALOG` 但 `.click()` 触发）。
- [2026-11-07][P1] 把历史"Dialog 无 max-width"欠账直接当坏样本，实跑却是真绿 ⇒ 欠账可能已修或不在目标包装组件（本次目标为 `w-100` + `max-w-full`，长标签换行） ⇒ 坏样本跑前先读当前源码/实测布局，再锁定档位；历史欠账只作候选，不作判据 ⇒ 证据：同上。
- [2026-11-14][P1] E04「窗口容纳不下保留视口并提示」的提示此前只写工具层第三行，而该行在 64px CSS 视口下被 `#bar` 裁掉 ⇒ 判据在当前 GUI 上不可观察，沿用 11-11 的「人工通过」会形成假绿 ⇒ 结果类判据先确认观察通道；本轮补状态栏红条并把该场景改列「人工待复核」，不沿用旧目视结论 ⇒ 证据：本文件 2026-11-12 裁切事实条、`main.ts` Viewport 分支与 [change 任务 5.2 对照表](../../openspec/changes/add-tauri-page-host/evidence-index.md)。
- [2026-11-14][P1] 同一轮人工复验里「旧场景通过、新场景全不通过」容易被记成多个功能缺陷 ⇒ 本质是验证对象版本不一致；新旧链路的反应差异就是判别信号 ⇒ 先用「旧代码路径是否仍正常 + 服务端产物是否含新标记」两点定位窗口版本，再决定要不要改产品；窗口版本未经自证的反馈既不计通过也不计失败 ⇒ 证据：A 组（3.x 旧链路）红条正常、Vite 返回脚本含 `lastViewSignal` / `窗口容纳不下` / `已返回原 WebView`，[首轮人工复验](../../openspec/changes/add-tauri-page-host/evidence-index.md)。

## 原生快照与原地预览（2026-11-12 真机）

- [2026-11-12][P1] 编译通过不等于「原生快照回调会来、图片能编码」 ⇒ `with_webview` 投递主线程、`takeSnapshot` 异步回调、NSImage→PNG 三段任一失败都只是编译期看不见 ⇒ 加 debug-only 探针（`LAYRESS_PROBE_CAPTURE=1`）在真机跑完整链路并核对落盘字节；本次 PNG 2560×1408 RGBA / 231915 B、开始到完成 47 ms、PNG 头可被 `file` 识别 ⇒ 证据：四次 `pnpm tauri dev` 探针 stderr 与 `target/debug/.layress/captures/*.png`（不入库）。
- [2026-11-12][P1] 截图尺寸 2560×1408 而逻辑视口 1280×704 ⇒ macOS WKWebView 快照按 DPR 2 出物理像素；元数据里逻辑视口与图片像素必须分列，CSS 坐标换算要用 `imageW / 页面实测 w` ⇒ 坐标相关判据一律以原图像素为准，样例页固定参照块按该比例换算；不把图片尺寸当 CSS 视口 ⇒ 证据：探针元数据 `bounds=[1280,704]`、`measured.dpr=2`、`image.width_px=2560`。
- [2026-11-12][P1] 「只截被测页面」靠视图级快照 + 互不重叠布局共同成立，不能只靠裁掉窗口顶部 96px ⇒ 工具层与被测层是两个 WKWebView，`takeSnapshot(nil)` 取各自 bounds；整屏截图仍可能混入其他窗口 ⇒ 保持视图级快照，失败就明确报错，不以整屏裁切兜底；**截图内容是否真的无工具层仍需人工目视复核** ⇒ 证据：change 任务 3.1 与 [设计](../../openspec/changes/add-tauri-page-host/design.md)。
- [2026-11-12][P2] 预览切换若用「隐藏 / 改尺寸 / 重建」会触发页面 resize 甚至重载，输入与弹窗状态丢失 ⇒ 本次改为只改被测层 position（平移到窗口外 2000px）且保持 size，工具层铺满窗口显示静态图 ⇒ 不销毁、不重载、不改视口；遮挡关系、返回后输入 / 弹窗是否保留**仍待人工复验**，会话标识只作机器观测 ⇒ 证据：`lib.rs::apply_layout` 与 change 任务 3.3 未勾选状态。
- [2026-11-12][P1] 工具层 WebView 的 CSS 视口实测只有 64px（Rust `bounds=Logical(1280×96)`、窗口 `Physical(2560×1600)`、`scale=2.0`） ⇒ 逻辑 bounds 与 WebView CSS 视口不相等，具体原因未定位（macOS WKWebView 布局 / 缩放相关），不能按 `TOOLBAR_H` 推断页面可用高度 ⇒ 工具层 UI 判据一律以 `window.innerHeight` 实测为准；反馈元素贴视口底部；`#bar` 96px 的第三行状态 / 视口 / 请求信息当前被裁不可见，列为 UI 欠账 ⇒ 证据：toolprobe 标题回报 `innerH=64` 与工具层 `takeSnapshot` 截图。
- [2026-11-12][P2] 同一窗口不同 child WebView 的 CSS 视口换算并不一致：工具层 bounds Logical 96 → `innerHeight=64`，底部状态栏 bounds Logical 42 → `innerHeight=42` ⇒ 不能拿一块的比例推断另一块，也不能用 Rust 常量直接当 CSS 高度 ⇒ 页面区高度统一由 Rust `stage_height()` 计算，状态栏自身布局按自己的 `window.innerHeight` 实测，并对状态栏 `takeSnapshot` 截图确认 ⇒ 证据：statusprobe 回报 `bounds=Logical(0,758) 1280×42`、`innerH=42`、`href=.../status.html` 与 `status-probe.png` 中可见的浅绿色诊断条。
- [2026-11-12][P1] 人工复验「采集期间导航 / 关闭」根本来不及触发 ⇒ 真实采集仅约 43 ms，人不可能在这么短的窗口里点按钮；把「没测成」笼统写成通过或「未测」都会丢掉「验证手段不可达」这一层 ⇒ 在开发构建加可控延迟（慢采 5 s，刻意卡在「已拿到 PNG 但未校验身份 / 写盘 / 显示」之间），并让 race 探针自动刷新核对不落盘（PNG 数 11 → 11）；**机器探针只证明逻辑生效，GUI 人工负例仍单列、任务 3.2 不勾选** ⇒ 证据：用户 2026-11-12 原话「采集的太快了导致我还来不及关」、[change 证据](../../openspec/changes/add-tauri-page-host/evidence-index.md) 与设计「开发期慢采开关」。
