# docs/knowledge/ · 经验库

> 本文默认以中文维护。

> 本目录是 Layress 的**可提交经验库**：开发中踩的坑、硬事实、不许重开的决定。
> 它存在的理由：前置项目把同类的东西放在本机记忆目录（`.workbuddy/memory/`）里，被 `.gitignore`
> 整目录排除，结果是 **clone 仓库的开发者或另一个智能体拿不到 90% 的经验**。本仓不再重复这个损失。
>
> 入口指针在 [`/AGENTS.md`](../../AGENTS.md) §六；条目格式与四条写法纪律以那里为准。

## 五个专题，按主题不按日期

| 文件 | 收什么 | 不收什么 |
|---|---|---|
| [`engineering.md`](engineering.md) | 构建、测试、门禁、依赖、openspec 用法上的坑 | 一次性流水、情绪 |
| [`runtime-probe.md`](runtime-probe.md) | 实机探针硬事实：CDP、窗口、DPR、输入法、时序、假绿判据 | 未实测的推测 |
| [`invariants.md`](invariants.md) | 不许重开的架构不变量，每条给出不成立时的后果 | 还开放讨论的选项 |
| [`decisions.md`](decisions.md) | 关键决策：决定了什么、为什么、代价 | 已被后续决定推翻的旧稿（进 change 归档） |
| [`debt.md`](debt.md) | 未决口径与欠账，标注归谁定夺 | 已有结论的事 |

## 回填纪律（什么时候必须写）

**开发中发现的问题、被推翻的假设、口径变更，必须在同轮写进本目录的对应专题。**
`.workbuddy/memory/` 是本机当日流水，被 `.gitignore` 排除；只写那里，别的 Agent 与 clone 仓库的接手人
一个字都看不到，**等于没写**。这正是本库存在的理由（见 [`/AGENTS.md`](../../AGENTS.md) §六、决策 D03）。
2026-11-08 本轮就复发过一次：迁移改造的坑先只落本机日志，经用户指出才回填。

提交前自检两句：

1. 这轮踩的坑 / 被证伪的假设，在五个专题里能查到吗？查不到就补，别留到"下次整理"。
2. 已定论进 `engineering.md` / `invariants.md` / `decisions.md`，未决进 `debt.md`，实机硬事实进
   `runtime-probe.md`（未实测的推测不收）；第二次踩按下面第 4 条升级成不变量或门禁断言。

本机日志只记当天流水与本轮索引；**规则、结论与判据以本目录为准**，冲突时以入库内容为准。

## 条目格式（固定，不许改成自由叙事）

```markdown
- [2026-11-03][P0] 现象 ⇒ 根因 ⇒ 规避 ⇒ 证据
```

- **级别**：`P0` 致命（数据损坏/结论作废）· `P1` 会导致误判（假绿/假红）· `P2` 浪费时间
- **一条一行一主题**。多主题就拆多条。
- **只写结论**，过程留在对应 change 的 `design.md` / `evidence-index.md`，本行只留指针。
- **同一坑第二次踩 ⇒ 升级**：写进 `invariants.md`，或直接变成门禁/测试断言。
  靠记性防的坑一定会再踩。

## 反面教材（为什么要有上面那几条）

前置项目的经验条目长这样：一行 400 字，把「窗口断点踩线 + 真键盘前台归属 + Monaco 计时瞬态 +
夹具重装导致 run id 变化」四件事用分号串起来，前面还挂着当轮测试计数。
它的信息密度极高，**但下一个接手人整段跳过**——因为它要求读者具备当轮的上下文。
本目录要求每条能冷读：不看当天日志也看得懂。
