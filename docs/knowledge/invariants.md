# invariants.md · 架构与口径不变量

> 本文默认以中文维护。

> **时效：以下 I1–I14 为封存阶段的历史编号，保留供查，不整体约束当前包划分、产品范围或接口设计。** 当前必须遵守的用户存储要求与工程纪律见 [`AGENTS.md`](../../AGENTS.md)，已确认产品要求见[产品依据](../product/product.md)与[当前 config](../../openspec/config.yaml)。需沿用的机制按实际设计与证据明确，不默认恢复旧四模块和三态协议。

> 这些条目**不许重开**。每条给出不成立时的后果——没有后果的"原则"只是措辞偏好，那种东西不该写在这里。
> 新增不变量的门槛：已经因为违反它吃过一次可测量的损失，或它是某个产品主张的唯一保障。

| # | 不变量 | 不成立时会发生什么 |
|---|---|---|
| I1 | **候选不等于缺陷**。几何异常只进入候选层，确认层产出三态判定（confirmed / not-a-defect / inconclusive），报告必须保留层的区分 | 报告退化成告警噪音，用户第一次误报后就不再相信任何一条，工具直接失去价值 |
| I2 | **可达性判定以真实命中测试为准**。程序化点击只能用于准备状态，不能用作"能点到"的证据 | 把被遮挡的操作报成可用——这是本产品的反向失效，比漏报更伤信任 |
| I3 | **触发条件四元组完整**：尺寸（宽×高）+ 界面状态 + 字体/缩放 + 语言。缺任一项 ⇒ 标记为不可回放，不许静默补全 | 换一台机器复现不出来，"可回放证据"这个交付物名存实亡 |
| I4 | **来源缺失、损坏或未知状态不得被 UI 猜测补造为可信事实**。宁可显示 unknown | 用户按猜出来的条件去修 bug，改错了地方，且回不来追溯 |
| I5 | **回放不新增真实外部副作用**；重跑必须显式授权并说明副作用与费用 | 一次"只读"的回放把目标应用的表单提交了 |
| I6 | **无需正确截图基线 ≠ 无需规约**。关键操作、准备步骤、可接受滚动、排除范围必须由开发者声明 | 工具开始替用户判定"什么算重要"，误报率与主观性同时失控 |
| I7 | **数据集物理分离**：调规则用的子集与最终评估子集不重叠，评估集不进入规则迭代回路 | 指标随规则上涨但外部项目一个缺陷都发现不了，首验结论作废 |
| I8 | **本地优先**：页面内容、截图、扫描结果默认不出本机。使用远程模型必须显式声明数据流与成本，且**不得静默降级为远程** | 客户界面数据在用户不知情下外发；这是法务级事故，不是隐私口号 |
| I9 | **缩减只有在保持失败的前提下才算完成**：每去掉一个条件都要验证仍能复现，不能为通过而丢弃必要前件 | 产出一个"最小复现"却根本不复现，开发者按它试一次就弃用工具 |
| I10 | **扫描 / 确认 / 缩减 / 回放四模块可独立使用**，且核心检测与报告完整开源 | 免费部分不足以独立完成一件事，开源只剩招牌 |
| I11 | **机器 PASS ≠ 人工通过**：视觉与交互判定归人工复核，未执行的复核单列 | 状态卡显示全绿而实际没人看过一眼，接手人据此继续推进 ⇒ 整段返工 |
| I12 | **便携优先 · 不写系统用户目录**（2026-11-08 由「不碰 C 盘」改名，承诺不变、三端等价）：数据、日志、缓存、临时文件写在产品自身目录或用户显式指定目录；**不得**默认写入任一端的系统用户目录——Windows `%APPDATA%`／`%LOCALAPPDATA%`／`C:\Users\…`／注册表／`%TEMP%`，macOS `~/Library/{Application Support,Caches,Preferences,Logs}`／`/private/var/folders`，Linux `~/.config`／`~/.local/share`／`~/.cache`。安装位置由用户选择，安装器不提权、不改系统 PATH。**写不进就不写**：目标目录不可用时明确报错并要求用户指定，**禁止静默回落到用户目录** | 拷贝目录不能整体迁移、删除目录留残留、企业环境写权限被拒、用户隐私数据散落在系统盘而不自知；"便携"退化成一种营销说法 |
| I13 | **数据目录解析口径唯一且可见**：优先级 `--data-dir` / `LAYRESS_DATA_DIR` > 产品目录下的数据根；解析结果（含是否可写）必须出现在启动输出、日志与报告头部 | 用户无法验证 I12 是否被遵守；同一份产品在两台机器上把证据写到不同位置，回放找不到原始数据 |
| I14 | **Agent 友好是产品接口约束**：扫描 / 确认 / 缩减 / 回放可发现、可非交互调用、可解析且可追溯；提供有版本的结构化输入输出契约，机器输出与日志分离，退出码区分执行结果，判定保留三态与未执行项，证据可衔接后续操作。UI、CLI 与未来 MCP / Skill 复用核心能力；非交互调用仍遵守 I5 / I8 / I12。详细接口约定见 [`openspec/config.yaml`](../../openspec/config.yaml)，当前尚未实现 | Agent 只能解析易变的自然语言或操作 GUI，缺参时无限等待，把运行成功或不确定当成缺陷检查通过，后续确认与回放无法可靠衔接 |

| I15 | **面向用户的操作反馈只走底部独立状态栏**（2026-11-13，add-tauri-page-host 两次「提示不可见」事故升级）：工具层 WebView 的 CSS 视口实测仅 64px，`#bar` 96px + `overflow:hidden` 会裁掉第三行；「已拒绝 / 失败 / 成功 / 进行中」等结果类文字必须经 `showStatusBar` → `status_bar_set`，工具层第三行只能作为该函数的兜底，不得单独承载结论 | 用户在 GUI 上看不到拒绝与失败，误判功能没跑或已成功；「明确失败」的规格形同虚设，任务被误标未实现并诱发多轮返工 |
| I16 | **人工复验前必须自证窗口内代码版本**（2026-11-14，旧 DOM / CSP 挡 HMR 坑第三次命中升级）：工具条显示由当前 `main.ts` 写入的版本徽标，`check-build.mjs` 断言该徽标与源码常量一致；徽标缺失、为「加载中」或版本不符时，本轮所有 GUI 观察结论作废 | 「重启过了」无法验证，人工复验会跑在改动前的 JS 上：新功能全被报成缺陷、旧功能照常通过，接手人按假反馈改代码 ⇒ 整段返工，真实缺陷反而被掩盖 |
| I17 | **动态创建的被测页面不得盖住状态栏**（2026-11-14 真缺陷升级）：多 WebView 桌面壳中，凡在启动期之后 `add_child` 的视图，必须随后把结果类状态栏显式提回最上层（macOS 用 `reparent`）；非 macOS 未实测时如实单列，不擅自套用 | 窗口缩小或设定视口较大时，后创建页面的 bounds 会与底部状态栏重叠，把「已拒绝 / 采集失败 / 容纳不下」整条盖掉；用户看到的是「功能没跑」，接手人按假反馈改逻辑，I15 形同虚设 |

## 与前置项目的差异（避免照抄）

- ReBaseAgent 的核心资产是**轨迹与快照的不可变性**（append-only、分叉不改父本）。
  Layress 没有"运行历史"这一层，`I3`/`I9` 承担同样的职责：**证据一旦不完整或缩减过度就作废**。
- ReBaseAgent 的 `I：代理捕获的 key 只在内存` 对应到 Layress 的是 `I8` ——
  外发的是**页面内容**而不是密钥，敏感级别同样高，且截图里可能带姓名、地址、内部路径。
- ReBaseAgent 已采用"便携版业务数据落 exe 旁 `data/`"的口径，Layress **沿用它并推进一步**：
  缓存与临时文件（含 Chromium/Electron 的 `sessionData`、`userData`）同样三端都不得落系统用户目录
  （Win 用户目录 / macOS `~/Library` / Linux XDG），
  见 I12 与 [`engineering.md`](engineering.md) 的"存储与便携"。
