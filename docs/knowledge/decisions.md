# decisions.md · 关键决策速查

> 本文默认以中文维护。

> 记录了"决定了什么 / 为什么 / 代价 / 什么条件下推翻"。**已定的事在这里查，不要在文档里重开辩论。**
> 被后续决定推翻的旧条目留在 `openspec/changes/archive/` 的 design.md 里，本表只留当前口径。

| # | 决定 | 理由 | 代价 | 推翻条件 |
|---|---|---|---|---|
| D01 | pnpm monorepo：`packages/<core\|confirm\|reduce\|replay\|cli>` + `apps/desktop` | 调研 §5.3 要求四模块可独立使用；桌面适配后置但必须预留位置，否则日后要从单包拆 | 前期目录为空，多一层 workspace 配置 | 首验证明四模块无法解耦（例如全部逻辑必须共享一个 in-page 探针运行时） |
| D02 | **文档默认中文，仅对外门面按需双语**（2026-11-04 收窄）；当前为根目录 README、CONTRIBUTING、SECURITY、CODE_OF_CONDUCT、CHANGELOG，同目录 `*.en.md` 且逐篇登记。内部接手索引、经验库、方案与维护说明无需翻译，11 份内部英文旧版仅本地归档于 `docs/drafts/2026-11-04-internal-translations/`，不入库 | 用户要求大部分文档中文即可，持续维护内部双语成本过高；对外文件仍可面向海外读者 | 对外版本须同轮同步；本地归档不随 clone 分发，已提交旧版可从 Git 历史查找 | 某篇文档出现明确的对外英文阅读需求时逐篇登记；不按目录扩张 |
| D03 | 经验库**入库**（`docs/knowledge/`），不放本机记忆目录 | 第 3 条要求：任何开发者或任何智能体 clone 后就能接手。前置项目 90% 的经验被 `.gitignore` 挡在仓库外 | 坑条目要写清"已验证/未验证"，不能像本机日志那样随便记 | 无 |
| D04 | 洁净度用**默认拒绝脚本 + 可审计豁免**，`.gitignore` 只做兜底 | 忽略清单是默认放行，一个 `add -f` 就把数百 MB 写进不可删除的历史；豁免必须带理由才有审计线索 | 每个克隆要跑一次 `git config core.hooksPath .githooks`；CI 多一步 | 无 |
| D05 | 只允许两个垃圾场：`artifacts/`（可重跑产物）与 `.layress/`（运行时数据/日志） | 前置项目的 `output/` 因为"随手放"烂掉，最后要靠注释解释历史迁移。名字越少，越没有第三选择 | 想扔东西要先判断归属 | 无 |
| D06 | 采纳 openspec 三段式（`config.yaml` + `specs/` + `changes/{,archive/}`） | 决策要有固定容器，权威性排序才立得起来（源码 > archive > specs > docs > 索引） | 依赖 openspec CLI 与工作流习惯 | change 规模长期小于 3 步，流程成本超过收益 |
| D07 | 表单类**不做两份**：GitHub Issue/PR 表单内并列双语，Gitee 侧纯中文 | 两份表单提交者不知填哪个，也无处比对口径是否等价 | 三个位置的口径要人工同轮对齐（脚本不查语义等价） | 海外贡献占比高到中文并列成为噪音 |
| D08 | 许可证 MIT | 与作者既有开源项目一致，依赖许可兼容性最容易核，生态接受度最高 | 无显式专利授权条款 | 出现需要专利条款的商业化路径或依赖引入 GPL 冲突 |
| D09 | GitHub + Gitee 双轨 CI 配置就位（`.github/workflows/ci.yml` 与 `.workflow/ci.yml` 跑同一条链） | 大陆网络访问与曝光渠道；两侧命令不一致会造成"本地绿一边红" | 两份 CI 定义要同步维护 | 单一远程已够用且镜像无人使用 |
| D10 | 首版形态 = **Agent 友好的 CLI + 可读报告 + 结构化结果**，允许接进现有测试脚本与 Agent 工作流；桌面 UI 后置（2026-11-04 补充，见 I14） | 调研 §5.3 与用户要求；先把检测/缩减/回放的可靠性做硬，机器接口与人类报告共享事实 | 早期没有可演示的界面；首版需设计可发现、非交互、有版本的接口契约 | 首验发现人工交互必需时可增加 UI；Agent 调用能力仍需保留 |
| D11 | 品牌名 `Layress`；分发用 scoped 包 `@layress/*` | 产品/GitHub/npm/`.com` 均未占用（调研 §5.5）；`layrr`／`layerr`／`layui` 同前缀易混 | scoped 包名需要 npm org；README 要显式区分近似名 | `layress.com` 注册失败且检索混淆实测严重 |
| D12 | 语言口径：产出默认中文，产品名保持英文；国际化 = 中国用户优先 + 具备海外发布能力 | 目标用户与积累价值都在中文侧；结构先备好，换目标用户不是国际化的含义 | 门面文档要同轮双语，写作变慢 | 无 |
| D13 | 本仓当前**只建结构、索引与门禁**，不装依赖、不写业务代码 | 首验方案尚未批准（调研 §七），先写代码会造出需要推翻的骨架 | 门禁暂时只有洁净度与双语两条真命令 | 首验方案批准，即刻进 workspace 骨架 |
| D14 | `docs/` 命名按用途与状态区分：作为当前依据的已批准方案、现行规则与已核实事实用 `<english-kebab-case>.md`，探讨、调研、待批提案与当次记录用 `YYYY-MM-DD-<english-kebab-case>.md`（2026-11-04，细则见 [`docs/README.md`](../README.md)） | 用户要求；从文件名区分稳定依据与历史过程，持续引用无需随日期变动 | 晋升或改名须修复引用、双语登记与路径记录；正文仍须声明状态与证据 | 文档生命周期变化，需要新的分类时重新评估 |
