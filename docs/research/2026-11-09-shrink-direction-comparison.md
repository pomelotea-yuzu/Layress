# D18 收口后的两条收缩方向对照

> 本文默认以中文维护。
>
> **状态**：2026-11-09 一次性调研记录 / 待批提案，**不是 GO 决策**，不批准功能、技术选型或开发排期。
> 依据：[决策 D18](../knowledge/decisions.md)（2026-11-08 用户选 A 收口）与
> [综合调研 §九](2026-11-05-user-needs-and-agent-augmentation-research.md)。
> 本文不启动开发、不建 workspace、不立产品 change（D13 / D18）；方向由用户拍板。
>
> **为什么要写**：D18 只给了两个收缩方向，没给「凭什么选、怎么算选错」。缺了这层，接手时容易退化成
> 「收口 = 什么也不做」或「换个名字重启探针」。本文把两条路线并排，写清证据边界、推翻条件与下一步判据。

## 一、共同起点（收口证据，结论与边界一起读）

| 证据 | 结论 | 边界（不许越界引用） |
|---|---|---|
| 第 1 轮盲测（2026-11-08） | C 页 3/3：DOM `click()` 触发回调、真实指针落在全屏遮罩上不触发 ⇒ 程序化点击绕过命中测试这一**机制分叉成立** | 验的是机制不是痛点；自造夹具不冒充真实缺陷样本；夹具 v1 的 `var status` 观测缺陷按冻结声明不修不重跑；人工真值未给（I11） |
| B 轮自主任务对照（2026-11-08） | 当前 Agent + Playwright 真实指针：直接点 `#target` 被遮罩拦截并超时，明确拒绝「假点击」，先关遮罩再点 `#target` 才生效 ⇒ **假绿痛点被反证** | 一次运行、一个自造页面、一个任务；模型名称与版本、步骤数、耗时未报；用户级身份与长期规则跨工作空间注入，「完全无上下文」前提不成立（注入不含本轮假设，不影响「有没有假绿」的观测） |
| [第二轮 GitHub 证据](2026-11-04-github-evidence-round-two.md) §三（2026-11-04） | breakhound 已有宽度区间扫描、状态探索与 CLI / 扩展 / MCP；ui-review 已有几何检测脚本与 Agent 压力配方；LocalePass 已有页面 × 语言 × 视口循环与报告 | 三仓**均未实跑**；社区信号薄（0–1 个 PR、无用户 Issue）；能力存在 ≠ 采用或效果已证实 |
| [综合调研](2026-11-05-user-needs-and-agent-augmentation-research.md) §五、§九（2026-11-05） | Playwright 的 actionability、trace、UI Mode、reporters、认证复用与 emulation 已覆盖基础任务的大半 | 官方声明、局部源码与现行实跑效果须区分；「列出协议名」不等于兼容 |
| B 轮执行端最后一句 | 同一几何遮挡是缺陷还是正常流程，取决于开发者声明的关键操作、准备步骤与排除范围 | 提示真正缺的可能不是检测能力，而是**判定口径的声明**；单条观察，不是已验证需求 |

由此得到收口后的硬起点：**独立的几何 / 可达性检测能力不构成差异点**。立项调研 §5.2 早已把差异点定为
交付形态（已缩减的触发条件 + 可回放证据），§7.7 的五种结果里有两种明确指向「给现有工具贡献或做插件」。
两条收缩方向都建立在这个起点上；任何重启必须绕过或推翻它，不能只换个名字重做探针。

## 二、路线 A · 开发者声明规约 + 可回放证据

- **主张**：把「无需正确截图基线 ≠ 无需规约」（I6）做成第一等交付物 —— 开发者声明
  （关键操作、准备步骤、可接受滚动、排除范围）+ 证据契约（触发条件四元组 I3、三态判定 I1、
  缩减保持失败 I9、未执行项 I11、Agent 可消费 I14）。先出规范 / 配置格式 / schema，**不写检测器**。
- **最小交付物**：一页规约草案 + 一份有版本的证据 JSON schema + 用 11-08 已有观测做一次纸面回填。
- **复用**：`openspec/config.yaml` 的 I1–I14 已有口径、两轮盲测观测、综合调研 §8.3 的记录项。
- **证据**：B 轮执行端主动区分「Bug / 正常流程」；Joplin J2 维护者因「极窄尺寸不值得承担修复风险」
  拒绝合并（[第二轮 GitHub 证据](2026-11-04-github-evidence-round-two.md) §四）—— 两者都指向判定口径而非检测能力。
- **代价 / 风险**：规约若没有真实项目愿意写、愿意用，就只是一份文档；不与任何现有工具绑定，落地路径仍需另选。
- **推翻条件**：至少一个真实任务里，按规约仍判不出三态之一，或判定了但触发条件不完整、无法回放 ⇒ 规约不是差异点。

## 三、路线 B · 转插件／上游贡献

- **主张**：把已验证的机制分叉（真实命中测试 vs 程序化点击）与可回放证据接到现有工具上，
  而不是自建第二个 CLI / 第二个报告器。
- **最小交付物**：一个候选上游的**只读**承接点核查（建议 breakhound：能力最接近、MIT、有扩展 / MCP 接口）
  + 一份「贡献或插件放在哪里」的位置说明。
- **复用**：breakhound 的区间扫描与状态探索、ui-review 的压力配方、Playwright 的 actionability 与 trace。
- **证据**：立项调研 §7.7 与 [11-07 闸门](../engineering/plans/2026-11-07-agent-native-evidence-gate.md) §三
  决策表第一行，都把「当前 Agent 或既有工具已以相近成本可靠完成」对应到「转插件 / 上游贡献 / 收缩 / 停止」。
- **代价 / 风险**：三仓都较新（维护集中在创建当天、无外部用户 Issue），上游响应与长期维护是主要风险；
  许可均为 MIT 但复用须保留声明；未实跑前不能谈效果。对外联系、发帖、提 Issue 或 PR 须另行授权。
- **推翻条件**：找不到明确承接点，或上游不接受、不维护 ⇒ 转 A 或二次收缩。

## 四、并排对照

| 维度 | A · 规约 + 证据 | B · 插件 / 上游贡献 |
|---|---|---|
| 是否写产品代码 | 前期不写（只出规范与 schema） | 需要适配代码，但不落在本仓 `packages/` |
| 是否违背 D13 / D18 | 不违背（不铺探针、不建 workspace、不立 change） | 不违背（前提是贡献给上游，不在本仓另起 CLI） |
| 先决证据 | 真实任务里存在「判不出是否算缺陷」的口径缺口 | 至少一个候选可运行且愿承接 |
| 现有证据强度 | 一条 B 轮观察 + 一条维护者取舍，**弱** | 竞品能力已核查但未实跑、社区信号薄，**弱** |
| 主要成本 | 写规范 + 纸面验证，最低 | 实跑候选 + 上游沟通（对外动作须另行授权） |
| 失败信号 | 纸面回填仍两解 / 无人愿意写声明 | 候选跑不动或上游无响应 |
| 下一步判据 | §五 第 2 项 | §五 第 3 项 |

两条路线的现有证据都不强，**本文不代为选方向**；§五 只给成本从低到高的验证顺序。

## 五、共同推翻条件与重启纪律

- D18 原文：出现**至少一个真实项目中、当前工具链确实给出假绿且可回放的证据**，或用户决定换目标用户／
  产品形态 ⇒ 届时**另立 change，不复活 D17**。
- 两条路线都不是「重启独立探针」的入口。若某一步需要造检测器、建 workspace 或立产品 change，
  说明已越过收口边界，必须先显式推翻 D18 并说清新目标与范围。
- 机器 PASS ≠ 人工验收（I11）：人工真值未给前，本文任何判据都不得写成「已验证」；
  竞品声明不得写成实跑结果；未执行项单列。

## 六、下一步判据（零代码、可证伪）

| # | 做什么 | 产出 | 跑前判据（满足才继续） | 不满足时 |
|---|---|---|---|---|
| 1 | 真实证据补齐（长期） | 至少一份真实项目里的现有检查记录 + 人工真值 | 存在一个真实任务：现有 Agent / 工具的结果无法判定「是否算缺陷」，且触发条件可回放 | 两条路线都缺痛点 ⇒ 按综合调研 §九 二次收缩，不硬找方向 |
| 2 | **A 的最小纸面验证（建议先做）** | 1 页规约草案 + 1 份证据 schema，用 11-08 已有观测回填，**不重跑夹具** | 同一份 B 轮观测在规约下判成三态之一，且触发条件四元组完整、可回放 | 仍能两解或条件缺失 ⇒ 规约不是差异点，转第 3 项 |
| 3 | B 的最小只读核查 | 一个候选上游的承接点说明（建议 breakhound） | 存在明确落点（如命中判定 / 证据导出接口）且维护活跃度可接受 | 无落点或无响应 ⇒ 转 A 或二次收缩 |

**建议顺序 2 → 3 → 1**：第 2 项成本最低，且直接检验 B 轮留下的唯一正面提示；第 1 项需要真实项目材料，
而本机 `docs/drafts/` 私有草稿不存在，按隐私口径不从入库文档猜造、不上传私有素材。

共同纪律：纯文档 / 只读核查；不建 workspace、不立产品 change、不 push（push 归用户）；
不把「纸面回填通过」写成人工验收；对外联系另行授权。
