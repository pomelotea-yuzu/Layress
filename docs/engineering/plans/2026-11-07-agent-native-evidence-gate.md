## 一、它回答什么，不回答什么

**回答**：在一个真实、反复出现的任务上，相比"当前强 Agent + 其自带工具"单独完成，
**Agent 原生的送达方式是否显著减少准备 / 排障 / 复核的重复劳动，并产出 Agent 能直接接手的证据**。
这是"为什么开始开发"的证据闸门，不是"检测准不准"的完整验证。

**不回答**：探针通道选型（R1/R2，归首验 S0）、通用检测精确率（归 S1–S3）、三端实机验证（归 D15 里程碑）。

**核心假设待证**：现有方案在"关键操作可达性"上给**假绿**——程序化点击绕过模态 top-layer "点中"
真实用户点不到的按钮（I2 的反向失效）。若当前 Agent 单独又便宜又对，假设被反证，闸门判停。

## 二、两段设计（先解"鸡生蛋"死结）

闸门要决定"要不要开发 Layress"，但对照里的"Layress 路线"现在不存在。故拆两段，第一段零代码即可跑：

### 第一段 · 痛闸门（零代码，研究阶段即可做）

只跑**路线 A**：当前强 Agent + 其自带浏览器/测试工具，单独完成基线应用上的真实任务（见 §五）。
人在旁记录并对真值负责：

- 是否在可达性上**假绿**（程序化"点中"真实用户点不到的关键操作，却报成功）；
- 能否**缩减到最小仍可复现**的触发条件（I9），还是换条件又重来；
- 人**介入纠正几次、耗时多少**；产出证据 Agent 自己接不接得上。

**不写任何 Layress 代码**，纯观察记录。这就是调研停点写的"下次第一步"。

### 第二段 · 解法闸门（仅当第一段证明痛存在）

造一个**一次性最小探针 spike**（进 `artifacts/`，不进 `packages/`，不算产品代码），
只做 Agent 做不到的那一件事：对关键操作跨条件出**真实命中测试判定**（`elementsFromPoint` / 真实坐标命中，
对照程序化点击）。让同一 Agent 消费其输出再跑一遍任务，量劳动是否下降。

方法论复用首验 S0 测量项 2（top-layer 下程序化 vs 真实坐标点击是否结论不同），不新造判据。

## 三、预注册判据与决策表（跑前写死，防事后合理化）

| 第一段结果 | 第二段结果 | 决定 |
|---|---|---|
| Agent 单独又便宜又对，无假绿 | 不跑 | **停 / 转插件 / 上游贡献**（调研 §九 反证触发） |
| 反复假绿 / 缩不动 / 人反复纠正 | 探针显著省劳动且证据可被 Agent 接手 | **GO**：第一个产品 change = 探针转正 + workspace 骨架 |
| 反复假绿 / 缩不动 | 探针没帮上 | **停或重想解法**，不硬开工（痛在但解法不对） |

"显著"的最低门槛（预注册，可在任务卡按基线细化，但跑前定死）：

- 假绿可测：至少 1 个**已知坏样本**上，路线 A 报"可达/成功"而人工真值判"不可达"；
- 省劳动：第二段相对第一段，人的介入次数或耗时下降，且给出原始计数（不只报百分比）；
- 证据可接手：第二段产出的结构化结果能被同一 Agent 非交互消费并继续确认/缩减（I14 的最小验证）。

## 四、最少指标与真值

砍到四项（源自调研 §8.3，不扩）：

1. 人的介入次数 / 耗时；
2. 假绿次数（对人工真值）；
3. 到首次有效结果的时间；
4. 证据可被 Agent 接手程度。

**真值来源**：基线应用的**已知坏样本**（历史欠账/已记录的假绿机制）+ 人工判定（I11）。
记录 Agent / 模型 / 工具版本、预算、人工帮助；小样本给原始计数与不确定性，不报单点百分比。
未执行项单列，机器观察通过不写成人工验收通过。

## 五、实验对象（抽象条件，细节见本地草稿）

对象须满足（具体项目与证据指针在本地草稿任务卡，不在本文）：

- 用户**自有、已打包、开发冻结**的 Electron 应用作稳定基线（无授权摩擦、真值免费、痛是亲历的）；
- 含**关键操作**（取消/确认类按钮，尤其在模态对话框里），标签可翻译，窗口可调窄；
- 有**真实 i18n 切换**与响应式布局；有**已知坏样本/欠账**可量假绿；
- 可用**隔离/合成数据离线**检查到目标界面状态，不碰真实账号与业务数据（I5/I8）。

任务形状沿用调研停点：**切换语言 → 返回编辑 → 打开并取消放弃确认 → 继续编辑**。
应力条件 = 窄窗 × 语言切换 × 注入长标签；观测目标是放弃确认对话框里"取消"按钮的真实可达性。

## 六、纪律与边界

- **这是实验，不是开发**：第一段零代码；第二段 spike 进 `artifacts/`（可重跑复原、不入库），不进 `packages/`，不违反 D13。
- **判据跑前预注册**：§三 决策表与门槛在跑前定死，任务卡细化后不回改。
- **不一次铺开**：一个应用、一个任务、一个关键操作；不铺多应用、不上三端、不引远程模型（I8，本轮 0 元远程调用）。
- **GO 之后才立产品 change**：闸门是发令枪前的取证；第一个产品 change（探针转正 + 骨架）在 GO 后按[开发流程](../../development/workflow.md)立项。
- **诚实**：未实跑/未复核单列；若结果是停，照停，不为了叙事硬开工。
