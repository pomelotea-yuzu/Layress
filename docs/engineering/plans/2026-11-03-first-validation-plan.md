## 一、要回答的唯一问题

沿用调研 §7.1，一字不改：

> 在真实页面上，相比朴素溢出规则及直接竞品，是否能在可接受成本内多发现有效问题，并降低无效告警与人工复现负担？

**这个问题有明确的失败出路**：调研 §7.7 的五种结果里，两种明确指向"不独立做"（给现有工具贡献或做插件、
收缩任务重新衡量收益），还有一种要求先补外部数据才准宣称通用能力。
如果本轮只是证明"我们能产出更漂亮的报告"，那答案是收缩，不是继续。

## 二、阶段划分

### S0 · 探针通道对照实验（先量一轮，不预设结论）

目的：产出探针选型决策（进 `decisions.md` 成为一条 D 级决策），并把 I12 的路径覆盖做成可验证判据。

固定样本：**3 个页面状态，答案预先人工确定**

| 样本 | 内容 | 已知事实 |
|---|---|---|
| P1 | 纯 Web 静态页（本地合成，无网络） | 宽度低于 X 时某按钮被底部固定栏遮挡且滚动后仍不可达 |
| P2 | Electron 应用的渲染窗口（自选一个自有页面） | 长路径文本使工具栏关键操作被挤出可视区 |
| P3 | 带动态状态页（侧栏展开 + 错误提示出现） | 只有该状态下才复现遮挡；否则正常 |

两条对照路线：

- **R1 Playwright 驱动**：不下载自带浏览器，走系统 Chrome（`channel: 'chrome'` 或显式 `executablePath`）；
  Electron 用其 `electron.launch()`；需要取证时开 CDP session 取 `DOM`/`Input`。
- **R2 裸 CDP 直连**：`chrome-remote-interface` 或自写 ws 客户端，等待与命中判定自己实现。

测量项（**每项重复 6 次**，全部记录原始计数，不只报百分比）：

1. **遮挡 provenance**：能否拿到"被谁挡住"的可核对来源（`document.elementsFromPoint` 与
   CDP 命中测试结果是否一致，遮挡元素 id 是否与人工判断一致）。
2. **真实输入语义**：在 `modal`／top-layer 下，程序化点击与真实坐标点击是否给出**不同**结论
   ——这是 I2 的反证项：**两者结论相同即说明该路线不能用来判可达性**。
3. **同条件复现一致率**：6 次重复中判定一致几次（对齐 §7.6 的复现成功率口径）。
4. **档位可控性**：DPR 1/2、缩放 100%/200%、内容区宽度能否精确设定并**读回实际生效值**
   （前置项目实测过"默认窗口宽度骑在断点线上"这一坑，本项就是量它是否复发）。
5. **Electron attach 稳定性**：启动/断开/端口归属，是否出现孤儿 dev host 静默换端口导致
   "探针看似正常但控件永远找不到"。
6. **I12 落点（硬判据，不是加分项）**：跑完整轮后**统计 C 盘用户目录的字节增量**
   （`%LOCALAPPDATA%`、`%APPDATA%`、`%TEMP%` 三个路径的递归大小差）。
7. **实现工时**：达成同样的"遮挡判定 + 滚动可达性"两条路线各需多少行代码、多少小时。

预写死的判据（防止做完再找理由）：

- R1 能把**浏览器缓存 / 临时目录 / profile** 三处全部指到数据根之下，且第 6 项实测增量≈0，
  并且第 1、2 项与人工判断一致 ⇒ **选 R1**。
- R1 无法完全驯服路径（仍有缓存落 C 盘），或启动体积/时间不可接受 ⇒ **选 R2**，
  并把自写等待层的范围**明确限制在遮挡与可达性判定所需的最小集合**，不扩。
- 任一路线第 3 项一致率 **< 6/6 且原因未定位** ⇒ **不许进 S1**：底层通道不稳定时，后面所有指标都是噪声。

产出：`openspec/changes/…/design.md` + `evidence-index.md`；一条探针决策进 `docs/knowledge/decisions.md`（中文）；
`runtime-probe.md` 里标注"未在 Layress 复核"的条目按实测改标为**已复核**或**已推翻**。

### S1 · 数据集建设（本方案最慢也最值钱的一段）

- 规模按调研 §7.3：**5–8 个真实项目、30–50 个页面状态，至少一半来自外部项目**。
- 结构覆盖：设置页、表单弹窗、表格工具栏、列表详情、侧栏、底部操作区。
- 配比建议：正例（真实历史缺陷）**≥ 20**，负例 **≥ 15**（合理省略、滚动区域、抽屉菜单、浮层、可折叠工具栏）。
  负例不是装饰：没有它们就无法回答"误报率"，只能自说自话。
- 每条样本必带**触发条件四元组** + 目标元素 + 遮挡元素（若有）+ 期望判定 + 来源引用（I3、datasets 口径）。
- `tuning/` ≤ 40% 且 `eval/` 冻结：**评估集不参与任何规则迭代**（I7）。这是本方案能否得出结论的前提。
- 外部缺陷挖掘方法：在候选仓库 issue 里按 `layout / overflow / truncated / i18n / cut off / hidden behind`
  等关键词检索，**核对其是否已修复**作为"真实缺陷"的证据；未核实的候选一律标 `unverified`。
- 授权：每个外部样本记 license 与再分发判断；含隐私的用最小合成页面替代（debt 里的未决项）。

### S2 · 三组实现（公平比较的前提是三组吃同一批样本）

| 组 | 内容 | 定位 |
|---|---|---|
| A | 朴素规则：`scrollWidth > clientWidth`、元素越出视口、bbox 重叠 | **下限基线**，几十行；不能打败它就没有工具 |
| B | 实际运行竞品：breakhound（区间报告 + 菜单/弹窗/Tab/折叠状态扫描，CLI/扩展/MCP/CI）、ui-review（内容压力配方 + 模型审阅）、LocalePass（本地化 QA + SARIF） | 记录版本或 commit、能否跑起来、能否喂同一批样本；**跑不动就如实写"未能运行"** |
| C | 拟议方法：几何候选 + I2 可达性确认 + 聚合 + 缩减 + 回放 | 被测对象 |

两种比较分开做（调研 §7.4）：

1. **相同压力条件**：三组吃同一份条件，比检测数与误报数——避免"覆盖更多条件"被误当成"更准确"。
2. **相同运行预算**：固定墙钟时间与模型费用上限（本轮建议 **0 元远程调用**，见 §四第 4 项），
   比各自找到的独立缺陷数与人工处理耗时。

无法运行的历史研究（ReDeCheck、VISER/VERVE 等）列为**方法参考**，不编造横向实测结果。

### S3 · 指标与人工复核

沿用调研 §7.5 的 8 项指标（独立真实缺陷数、告警精确率、无效告警绝对数、复现成功率、
人工处理时间、缩减收益、运行成本、已知缺陷覆盖率）。两条硬规矩：

- **机器 PASS 不等于人工通过**（I11）：可达性/视觉判定由人复核，尽量两人独立，争议项记依据；
  未执行的复核在项目状态里单列"未执行"，不许勾完成。
- **小样本不报单点百分比**：同时给原始计数与不确定性（如 `C 组 12/14 成立`），
  分母与评价样本清单必须公开。
- 额外证据：外部项目**维护者是否认可或修复**，比我们的自评分更值钱。

### S4 · 结论与 go/shrink 判定

对着 §七 的门槛打分，按调研 §7.7 的五种结果选下一步；结论写成一份带原始数据的报告
（`docs/engineering/reports/YYYY-MM-DD-first-validation-report.md`），**允许得出"收缩"的结论**，
并且如果结果是收缩就照做。

## 三、时间盒与预算（建议值）

单人开发，**上限 6 周 / 约 90 小时**，含竞品运行与人工复核时间。分配建议：
S0 10%、S1 40%、S2 30%、S3 15%、S4 5%。

**S1 占 40% 是刻意的**：调研把数据集列为最有积累价值的资产，而"只有自制坏页面和自有项目表现好"
恰恰是 §7.7 里"暂不宣称通用能力"的触发条件。时间不够时**砍 S2 的 C 组功能，不砍 S1 的样本量**。

到期即判，不追加周期。这是防止"工具只对自家结构有效却被当成通用能力"的唯一机制。

## 四、需要你拍板的六件事

方案能不能批，取决于这六条；每条我都给了倾向，但归你定：

1. **时间盒**：6 周 / 90h 是否成立？还是压到 3 周只看 S0 + 小规模 S1？
2. **外部项目候选**：具体哪几个仓库？其中有没有你能直接问到维护者的（"认可/修复"证据的可行性）。
   我这边**尚未核查候选池**，这是 S1 的第一步工作，不是已完成的事。
3. **人工注入缺陷**：允许作为补充（调研 §7.3：可做补充，不替代真实缺陷）？
4. **远程视觉模型**：建议**本轮不引入**。C 组先只用本地几何 + 真实命中测试；
   一旦引入，I8 要求的数据流与成本声明会立刻变成产品面工作量，且调研已指出"结合 AI 看图"不构成差异。
5. **数据集入库授权**：外部开源项目的页面样本与截图能否入库、以什么形态（原件／派生／仅描述）？
   对应 `docs/knowledge/debt.md` 的未决项。
6. **公开节奏**：`layress.com` 与 npm org `@layress` 现在占，还是等验证结论？（与验证无关，只影响宣传时点）

## 五、本轮明确不做

审美评分、自动修复、任意应用全自动探索、最小 HTML/CSS 自动抽取、全平台全浏览器矩阵、
大规模多语言×字体矩阵、远程视觉模型（除非 S3 中出现"本地判定确实不够"的具体证据）。

**这不是把范围缩小好做一点**，而是调研 §7.2 的原始边界；扩大范围会让 §一 的那个问题无法被回答。

## 七、失败会是什么样（预先写死，避免事后合理化）

- 三组在同一批样本上的**独立缺陷数差异落在噪声内** ⇒ 我们的检测能力与朴素规则/竞品等价 ⇒ 收缩或做插件。
- 精确率高但**只在自有页面达成**，外部项目样本上误报成堆 ⇒ 通用性未证实，暂不宣称，补外部数据。
- 复现成功率达不到门槛 ⇒ 先修通道与时序，不进指标比较阶段。
- 人工复核时间没有被压缩 ⇒ 报告的"可回放证据"价值主张不成立，回到 §一 重新定位。
