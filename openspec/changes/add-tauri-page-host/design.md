# 设计：Tauri 单窗口页面承载与采集

> 状态：**实施中，2026-11-11；任务 1.x–2.x 代码已落地并通过编译与真实启动，运行级 / 人工验收未执行**。
> 本 change 只覆盖[第一阶段计划](../../../docs/product/2026-11-10-stage-one-plan.md)的首个“窗口与页面承载”增量。
> Tauri 已确定（D25）；本设计不将技术验证结论或其余阶段范围写成已经成立。

## 范围与交付

目标是一版单窗口、单活动页面的可运行基础：输入地址 → 操作页面 → 设置基础视口 → 采集 → 同位置静态预览 / 临时矩形 → 返回原页面。
临时矩形只验证后续批注能否准确落在画面上，本次不创建反馈任务、描述表单、数据库或完整标注工具。
首轮 macOS arm64，使用一个可重跑的本地普通页面样例；其他平台和复杂站点限制明确列为未验证。

## 已核对的 API 事实与待验证点

2026-11-10 读取当前 [Tauri WebviewBuilder 文档](https://docs.rs/tauri/latest/tauri/webview/struct.WebviewBuilder.html)和[Window 文档](https://docs.rs/tauri/latest/tauri/window/struct.Window.html)：

- `Window::add_child` 支持同一窗口内多个原生 WebView，目前限桌面且要求 Cargo `unstable` 功能。
- 文档明确 `data_directory` 在 WKWebView 不可用；`data_store_identifier` 是标识符，不是任意目录路径，不能拿它证明满足便携存储。
- `incognito` 在 macOS 使用非持久数据存储；这支持首轮使用临时会话的候选做法，**不证明运行期零写盘或系统目录没有残留**。
- 文档提示 Windows 的同步回调 / 命令中创建 WebView 可能死锁，后续平台接入需核对应异步 / 线程限制。

上述 `latest` 页面不是依赖锁定版本。实施时选择并固定具体 Tauri / Rust / 前端依赖，重新核对对应版本 API；记录 `unstable` 功能依赖与更新代价。
建档时 PATH 未找到 `openspec`、`cargo`、`rustc` 或 `pnpm`，这不是整机安装状态结论。随后用户授权在仓库外共享安装 OpenSpec 1.17.0，已完成严格规格校验，入口见[工作流](../../../docs/development/workflow.md)；Rust / pnpm 等产品工具链与上述 API 运行仍未验证。

**数据根解析（I12 / I13，E09）**：优先级 `--data-dir` / `LAYRESS_DATA_DIR` > 可执行文件目录旁 `.layress/`；启动横幅、日志与后续报告头部显示解析结果与可写检查；不可写明确报错，不回落系统用户目录。开发运行时 exe 在 `src-tauri/target/debug/`，数据根随产物目录走，`target/` 已被忽略。此为定稿口径，代码在任务 4.1 实现。

**权限边界（E02 / E13）**：Tauri v2 capabilities — 本地工具 WebView（label `main`，加载 devUrl/dist）持有 `core:default`；被测页面 WebView 使用独立 label，**不出现在任何 capability 的 windows 列表** ⇒ 无任何原生命令能力。导航只放行 HTTP(S)（`on_navigation` 拦截其他 scheme）；新窗口、下载、设备权限请求在 Rust 层明确拒绝并反馈（任务 2.3 / 4.3 实现并留负例证据）。不给页面暴露通用原生桥。

**会话与写盘（E10）**：首轮工具与被测 WebView 均用非持久会话（macOS `incognito` ⇒ 非持久 data store）；不设 `data_directory`（WKWebView 不支持）。跨重启登录态丢失是已知代价，界面如实说明；非持久 ≠ 零写盘，真实写盘观测按 E10 方法执行。

**快照候选（E05）**：macOS WKWebView 原生 `takeSnapshot` 经 wry / objc 桥接为首选候选；Tauri 无现成跨平台截图命令，实施时先核实 wry 是否暴露该方法，不假定可用，失败再评估其余候选并如实记录。

**为何不是替代方案**：iframe 拿不到独立进程 / 会话隔离与真实视口控制，也不能承载跨域站点；默认系统持久存储直接违反 I12。普通 `Window` 双窗口搬运会破坏"同一工作区原地预览"的目标形态。

## 窗口与权限边界

一个原生主窗口内包含本地可信工具 WebView 与独立的被测页面 WebView。Rust 层协调页面位置、尺寸、导航、采集和生命周期。
优先通过 Tauri 的多 WebView 路径实现；原生嵌入、z-order、遮挡和焦点要在最小骨架中验证，不用普通 iframe 代替目标网页。
可信界面采用 TypeScript strict 和最少构建依赖；首个骨架不为尚未出现的复杂界面提前固定完整 UI 框架。
被测页面没有 Tauri 原生命令、文件或进程权限；按 WebView 标签与可信来源限制命令能力，不开放通配远程域。
不得为了取得尺寸或截图给页面暴露通用原生桥；页面状态采集由受控内部通道完成，取得不了的信息显式缺失。

允许用户输入明确的 HTTP(S) URL，包括本地开发服务；拒绝不支持的 scheme 与无效地址，不执行 `file:`、`javascript:` 或自定义系统处理器。
网页普通导航留在被测视图；新窗口、下载、设备权限等未经支持的请求明确处理，不自动创建额外顶层窗口、写未知下载目录或启动外部程序。
第一轮样例包含点击、输入、滚动、路由 / 链接和页面内弹窗；不默认继承日常浏览器登录，不自动启动用户项目服务。

## 视口与画面

工具栏提供基础宽高设置，不做设备库或预设记忆。用页面实际值核对配置，记录逻辑视口、原生区域、DPR、截图像素尺寸与展示比例的关系。
首轮选择两个能在本机工作区验证的尺寸，实际值在证据中登记，不把样例尺寸当产品永久范围。
窗口和工具区变化不能静默更改已选择的页面视口；无法容纳时明确提示或提供不改变视口的展示方式，不假装已实现全画面缩放。
真实页面的缩放 / 原生子视图尺寸和静态截图缩放分开，不能把 CSS `transform` 自动当成可缩放原生 WebView 的方案。
静态预览至少验证原始比例和适应区域两种展示下的临时矩形，坐标存为原图空间，校验落点不因显示缩放漂移。

## 采集与预览

Rust 层按当前页面身份发起仅限目标 WebView 的采集；macOS 原生 WebView 快照作为候选实现，具体桥接、线程和回调在实施时验证，不假定 Tauri 有现成跨平台截图命令。
不以 DOM 重绘或整屏截图静默替代；前者可能遗漏真实渲染，后者可能混入工具层和其他应用。
每次采集分配独立标识，保留 schema 版本、页面身份、实际 URL、开始 / 完成时间、视口、图片尺寸以及可取得的 DPR / 滚动条件。
读取条件或采集期间若页面已导航、切换或关闭，判定本次失效并提示重试，不把旧图绑定到新地址；记录开始 / 完成条件差异，不承诺动态画面绝对原子快照。
采集成功后隐藏被测视图、在原工作区显示图片和临时标记；从静态预览返回时显示原 WebView，不销毁或重载来假装保留现场。
页面脚本与请求可能继续运行，界面标为“已记录画面”，不声称冻结业务；返回后不保证动态数据仍与截图相同。
采集失败不得显示上一张图为本次成功；原图、临时标记与页面身份分开管理，下一次采集不自动继承上一张图的标记。

## 数据根、会话与退出

启动先解析明确的数据根：产品可写目录下 `.layress/` 或用户显式指定目录；显示实际落点并验证可写，不采用系统用户目录兜底。
数据根解析不能依赖不可预测的启动工作目录；开发 / 打包位置的解析规则在实现时定稿，首次引入任何写盘前验证。
截图、元数据、日志与本次临时文件均放该根内；派生截图为运行时资料，不入库，不新增第三类垃圾场。
首轮工具与目标 WebView 都优先采用非持久会话，临时会话会丢失跨重启登录状态，应明确说明，不许回退为系统默认持久目录来保留登录。
即便启用非持久模式，也必须观测 WebView 缓存、网络、日志与临时文件。若产生不符合承诺的写入，记录具体位置、原因和可行修复，不能把 identifier 配置或 API 调用成功写成便携通过。
写盘验证先用隔离夹具内已知根外写入证明观测链能检出，再结合真实运行的文件事件、进程身份与时间窗口、目录前后对照排除背景活动；细则见[证据计划 E10](evidence-index.md)。已知坏样本未检出、工具权限不足、事件丢失或 WebView 辅助进程覆盖 / 归因不清时标为失败或不确定，不能判便携通过。
若无法在 Tauri 内满足当前存储或页面约束，记录受影响场景与候选调整；不静默换壳、附带另一套浏览器或删掉便携要求。
退出清理本次视图与后台资源，取消待完成采集，不误删产品目录外文件；持久截图按记录策略留本地，临时探针产物可清理。

实施时最小预计结构为根 pnpm 配置、`apps/desktop/` 前端与其 `src-tauri/` Rust 工程；创建前登记到文档地图与应用归属，不预建无用 packages。

CI Ubuntu 能执行的检查不能被写成 macOS 原生快照已经验证；macOS 实机证据仍需单列，不把它伪装成云端通过。

当前不发布 CLI，但数据和采集机制不能只存在于界面组件；未来 CLI 围绕同一份本地事实扩展，不建立第二套现场记录。

## 取舍与后续

没有选择普通 iframe、手工双窗口搬运、自动换回 Electron、整屏截取兜底或仅用截图假装交互页面。
首轮采用临时会话与基本宽高控制，换取尽早核实承载、截图、原地预览和权限；设备库、会话恢复与完整反馈分别在后续增量实现。
Tauri 多 WebView 的不稳定 API、原生快照和 macOS 写盘限制是本次需要解决的技术问题，不是要求重新证明市场空白的前置闸门。
本 change 完成后才进入项目 / 设备记忆等下一增量；完整验收要求见 [spec](specs/desktop-page-host/spec.md)，完成状态只在 [tasks](tasks.md) 维护。

## 任务 3.x 实施定稿（2026-11-12）

本节记录代码级决定；**实施完成状态以 [tasks](tasks.md) 的勾选与人工复验为准**，机器检查与人工验收分列。

**真实截图（E05）**：`tauri::Webview::with_webview` 在 macOS 取得 WKWebView 指针，
调用 `takeSnapshotWithConfiguration:completionHandler:`（配置传 nil ⇒ 只取该视图 bounds），
回调的 `NSImage` 经 `TIFFRepresentation` → `NSBitmapImageRep` → `representationUsingType:PNG` 得到 PNG 字节。
实现只用 `objc2 0.6.5` / `block2 0.6.2`（与 wry 0.57.2 间接依赖同版本），经 `msg_send!` 调用，
不引入额外 WebKit / AppKit crate。快照天然不含工具层、其他窗口与屏幕背景；
`takeSnapshot` 期间先移除工具注入的视口边框（工具标记），完成后恢复。
非 macOS 平台明确返回「未实现」，**不**回退整屏截图、DOM 重绘或空白图。
图片尺寸从 PNG IHDR 读取，不依赖平台返回的 points 尺寸。

**版本化元数据**：`layress.capture/v1`，`apps/desktop/src-tauri/src/capture.rs` 强类型定义。
含采集 id、页面标签与**实际 URL**、导航代号、开始 / 完成 Unix 毫秒、设定 / 边界 / 页面实测视口、
PNG 尺寸与字节数、引擎与方法、滚动条件、`missing[]`（取不到或本次不验证的条件逐条写明）、数据根绝对路径。
产物为数据根下 `captures/<id>.png` + `captures/<id>.json`；只有身份校验通过的采集才落盘。

**竞态与旧图隔离（E06）**：`CaptureState` 用 `generation`（任何导航 / 刷新 / 视口变更 / 窗口关闭递增）
与 `seq`（每次采集递增）标识请求，结果回来时须 `is_current` 才允许写盘与显示。
导航意图、页面自身 `on_page_load Started`、视口变更、窗口 `Destroyed` 都作废在途采集；
新采集请求自然替换旧请求；失败 / 取消只清在途状态，**不触碰 last**（旧图只作旧现场，界面单独标注）。
状态机与 PNG 尺寸解析、base64 编码有 `cargo test --lib` 纯逻辑单测（5 项），
但「采集期间真实导航 / 关闭」的运行级负例仍需 GUI 或探针实测，未执行项单列。

**原地预览（E07 / E08）**：不新建顶层窗口，也不销毁被测视图。
预览态把工具层 WebView 铺满窗口、把被测层**仅平移出可视区且保持尺寸不变**（只改 position）；
工具层内显示静态 PNG、模式切换、临时矩形与元数据。尺寸不变 ⇒ 不触发页面 resize，返回时只恢复位置，
页面会话、输入与弹窗不因工具切换被销毁或重载。初始化脚本为每个 document 生成 `session` 标识，
经 title 哨兵回报；返回后重新上报一次，标识变化会提示「页面可能被重载」，但**不代替人工核对输入与弹窗**。
页面脚本与请求在预览期间仍可继续运行，界面标为「已记录画面」，不声称业务暂停或动态数据仍一致。

**坐标换算**：矩形唯一存原图像素坐标（`capture-start` 拖拽时由显示坐标除以 scale 归一），
渲染时才乘 scale；`src/coords.ts` 提供纯函数与运行时往返自检（两种模式、多组缩放，结果直接显示在界面）。
样例页加固定参照块（视口 CSS (24,24) 160×60），按 `imageW / 页面实测 w` 换算成原图坐标，
在原始比例与适应区域下核对同一区域是否漂移。DPR 导致的像素 / CSS 差异由此显式暴露。

**数据根**：3.x 必须先有明确落点才能写盘，因此先行实现最小解析与可写检查
（`--data-dir` / `LAYRESS_DATA_DIR` > 可执行文件旁 `.layress/`）、启动横幅 / 事件 / UI 显示与
「采集前再查一次可写」。这是任务 4.1 的**部分代码**，4.1 的不可写负例、写盘观测与完整验收仍未完成，不勾选。

**开发期探针**：仅 debug 构建且显式 `LAYRESS_PROBE_CAPTURE=1` 时，自动打开样例页并采集一次，
把结果打到 stderr，供无人值守核实原生快照链路；`=race` 则在慢采窗口内自动刷新，核对结果失效且不落盘。
两者都不参与默认路径，不代替人工验收。

**开发期慢采开关（2026-11-12 补）**：真实采集约 43 ms，人工根本来不及在「采集未完成」窗口内
触发导航 / 关闭——用户复验第 4 项时明确指出这一点，因此该负例不是「没测」而是「手段不可达」。
工具条新增「慢采 5s」复选框（仅开发构建显示），`capture_start` 接受 `delay_ms`；
Rust `capture_delay` 只在 debug 生效、上限 15 s、默认 0，产品路径零影响。
延迟刻意卡在「已拿到 PNG，但尚未校验身份 / 写盘 / 显示」之间，期间刷新 / 取消 / 再发一次采集
都应立即让本次结果失效，界面提示到数据根 `captures/` 核对无新文件。
race 探针给出运行级机器证据（PNG 数 11 → 11）；用户于 2026-11-12 用该开关在 GUI 上完成同类负例并确认「流程验证成功」，**任务 3.2 已勾选**。

**结果条最终形态（2026-11-12 用户选定）**：工具层 WebView 实测 CSS 视口只有 64px，任何浮层都会压住工具栏，
