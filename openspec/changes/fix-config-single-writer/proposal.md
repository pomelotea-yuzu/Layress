# 修复同一数据根的配置写锁

> 2026-11-19 用户授权建档。独立 Agent 已审阅，规划意见已处理，产品实施与本轮实机复验待执行。见[审阅及处置](review.md)。

## Why

2026-11-18 的 macOS arm64 实机复验中，两个 Layress 桌面进程打开同一数据根，第二个实例的设置面板仍显示「可写」。当时的存储模块子进程测试通过，桌面进程报告可写的原因及当时实际持锁状态仍待核实。若两个实例都提交配置，可能各自从旧 revision 写入并覆盖对方。[实机记录](../archive/2026-11-18-add-project-device-profiles/evidence-index.md) · [P1 欠账](../../../docs/knowledge/debt.md)

## What Changes

- 以同一实际数据根内的 `config/projects.lock` 作为项目配置的唯一写入仲裁。核对桌面启动、命令、后台地址记忆、重建和退出各路径，确保写入与持锁实例一一对应。
- 被占用的实例以只读方式显示可用配置，允许按快照恢复项目和临时浏览。配置写操作返回 `CONFIG_LOCKED`，底部状态栏给出原因。只读期间发起的导航不记忆最近地址，也不积攒待补写意图。
- 持锁实例退出后，另一实例可在设置中显式重取。按「取得锁 → 重读并校验磁盘 → 发布配置和 revision → 开放写入」完成交接。重读失败只给出错误，仍禁用常规写入。
- 启动时发现损坏配置或未知版本，报告内容错误并禁写，释放本次取得的锁。经用户确认的备份重建再申请同一锁，连续持锁完成复查、备份、原子替换和新状态发布。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `project-device-profiles` 的「最近地址的事实记忆」和「提交失败与并发保护」。见[规格增量](specs/project-device-profiles/spec.md)。

## Impact

- 涉及 Tauri 配置存储和桌面编排，以及工具层设置面板。配置保留 `layress.project-config/v1` 与原数据根布局，沿用现有错误码、可信工具层权限和底部独立状态栏。
- 该锁的范围是项目配置、备份及相关临时文件。原地批注、设置态导航与布局两项欠账、D30 发行写盘观测各沿既有计划处理。
- 收口需用真实桌面二进制证明同根互斥、跨根独立及退出后的安全交接。机器测试经现有公共门禁运行，macOS arm64 实机项逐场景登记，其他平台按实际验证情况列明。见[实施任务](tasks.md)和[证据索引](evidence-index.md)。
