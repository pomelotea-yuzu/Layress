# 实施任务

本轮为规划建档。任务随各自证据通过后勾选，见[证据索引](evidence-index.md)。

## 0. 核实实机故障

- [ ] 0.1 用现有构建运行同根双桌面进程，核对实际 PID、运行版本；先核对两进程解析后的绝对数据根、来源及锁文件设备号 / inode，再核对锁探测、有效写命令结果及配置前后字节。记录 `writable` 快照与持有句柄的生命周期。记录可重现条件或未复现的边界。梳理启动至退出的所有锁句柄和配置写路径，明确已证实问题与假设。（E01）

## 1. 实现同根单写入者

- [ ] 1.1 统一配置存储、启动状态及提交入口的持锁状态。在 `OnceLock<ConfigStore>` 的共享引用约束下，把写入许可、锁句柄、快照及 revision 放在同一内部串行裁决点。建立同根、路径别名、跨根、已有空锁文件的机器反例，证明仅真实持锁者可写，其他根各自独立。保留原子写入、写失败及中断回归。（E02、E06）
- [ ] 1.2 收敛配置修改命令的只读判定，覆盖创建、重命名、编辑地址、视口与旋转、切换、未保存重试及备份重建。明确 `config_retry_unsaved` 的只读请求以 `CONFIG_LOCKED` 拒绝，即使没有待保存意图。保留 `startup_restore` 的只读快照恢复；`remember_last_loaded_url` 对只读期间发起的项目归属导航、重定向和临时浏览跳过持久化、`UnsavedState` 及未保存红条。验证文件字节、revision、项目 / 页面状态及备份数。（E02、E03）
- [ ] 1.3 在设置中接通显式重取操作，分别实现争用返回、取得后先验证并读新 revision、失败释放锁且禁写。同步前端快照，阻断重取前的待处理配置意图及旧页面回调；验证新提交、过期 revision 和重复请求。结果走底部状态栏，前端源码改动同步递增徽标并登记指纹。（E04、E06）
- [ ] 1.4 启动读到损坏或未知版本即报告内容错误并释放本次取得的锁。显式重建只申请一次，复用已持有的锁句柄完成复查、备份、替换与发布，再交付存储；用同步点证明竞争方不能在交付空档取得锁。测试已恢复的文件、备份失败、备份上限及原字节 / 旧截图保护。（E05、E06）
- [ ] 1.5 核对正常退出时已开始事务与未执行意图的顺序，以及异常退出后 OS 释放锁。验证正在重取、采集或导航的实例退出时，旧结果不会提交；接任者读到最新完整版本。（E04、E06）

## 2. 验证与归档

- [ ] 2.1 把新增机器测试接入现有 `cargo test --lib` 与 `check-repo.mjs` 覆盖入口。实跑公共链与 OpenSpec strict 校验，记录命令、退出码、用例数、平台及已知坏样本是否判红。（E06）
- [ ] 2.2 在 macOS arm64 用两个真实桌面进程完成同根争用、只读启动恢复与后续导航、退出后重取、跨根写入和损坏配置重建复验。使用 E05 的机器同步点验重建竞争窗口。核对真实二进制与窗口徽标、结构化错误、状态栏和文件结果；将未执行项单列。（E02–E05）
- [ ] 2.3 实机判据完成后同步 app README、欠账和接手状态，将规格增量合入主规格并归档。记录 Windows / Linux 和 D30 实际覆盖情况。（E07）
