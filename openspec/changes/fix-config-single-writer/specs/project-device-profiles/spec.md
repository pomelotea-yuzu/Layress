## MODIFIED Requirements

### Requirement: 最近地址的事实记忆

系统 MUST 将可归属当前项目的主文档完成加载实际 HTTP(S) 地址与起始地址、地址输入草稿区分。系统 MUST 仅在持锁发起且完成时仍有写入资格的项目导航中更新最近地址；失败、取消、过期或只读期间发起的导航不得更新。记忆地址不等于验证 HTTP 状态或业务成功。首版 MUST 明示仅覆盖主文档加载，不承诺未观测的 SPA history / hash 变化。

#### Scenario: 导航完成与重定向

- **WHEN** 持锁实例发起的当前项目导航正常完成，包含可归属的重定向完成，且仍有写入资格
- **THEN** 最近地址记录最终实际 URL，起始地址独立保留，系统不声称业务已通过

#### Scenario: 导航失败或仍是输入草稿

- **WHEN** 用户只编辑地址草稿，或导航因预检失败 / 错误 / 取消未完成
- **THEN** 已记忆的最近地址不变；失败时明确区分目标地址与旧页面实际地址

#### Scenario: 只读实例启动恢复活动项目

- **WHEN** 实例启动并读取到有效配置及活动项目，但未取得写锁
- **THEN** 从只读快照恢复视口并尝试打开记录中的页面，启动导航遵守只读导航的记忆限制

#### Scenario: 只读导航完成

- **WHEN** 只读期间发起的恢复导航、项目归属导航、重定向或临时浏览完成，包括显式重取之后才到达的完成事件
- **THEN** 可以显示导航结果，该回调不更新最近地址或磁盘 revision，也不生成待补写意图或显示「未保存 / 可重试」提示

### Requirement: 提交失败与并发保护

系统 MUST 串行验证并原子提交配置，仅在正式文件提交成功后发布已保存状态；写入失败或中断不得截断最后完整配置。对同一实际数据根，所有项目配置写入（含备份重建）MUST 受同一个跨进程独占锁保护，且持锁凭证覆盖整次写入及结果发布。第二实例无配置写锁时 MUST 明示只读并以 `CONFIG_LOCKED` 拒绝配置修改；过期 revision 不得覆盖新配置。获取或重取锁后 MUST 在开放写入前重读并验证磁盘配置。

#### Scenario: 写入或替换失败

- **WHEN** 在写临时文件或替换正式文件时发生错误
- **THEN** 原正式文件字节保留，显示保存失败；跨项目切换不开始，当前项目内已生效但未保存的条件明确标识并可重试

#### Scenario: 配置提交中断后重新启动

- **WHEN** 在临时文件写入和原子替换的不同阶段中断进程后重新启动
- **THEN** 读取到旧完整版本或新完整版本，不能把半份 JSON 当有效配置，未提交意图不被宣称已保存

#### Scenario: 第二实例争用配置

- **WHEN** 两个实例打开同一实际数据根，且一方已取得写锁
- **THEN** 只有持锁方能修改配置；另一方在设置中明确显示配置只读并展示可用快照，创建、编辑、视口保存、项目切换、重试保存和备份重建等配置修改命令以 `CONFIG_LOCKED` 拒绝，底部状态栏提示；只读期间发起的导航遵守「最近地址的事实记忆」要求，配置字节、revision 与备份均不因该实例的只读操作改变

#### Scenario: 两个数据根独立写入

- **WHEN** 两个实例各自打开不同的可写数据根，其中一个根留有未被进程持有的既有锁文件
- **THEN** 两个实例分别验证并保存各自的配置，锁文件存在本身不触发只读，两个根的配置与 revision 独立

#### Scenario: 持锁进程退出后显式重取

- **WHEN** 只读实例请求重取配置锁，随后持锁实例正常或异常退出，且只读实例再次显式重取
- **THEN** 锁被占用时保持只读并返回 `CONFIG_LOCKED`；退出后仍须显式重取，取得锁后先重读并验证磁盘最新配置和 revision，再开放写入；旧草稿、旧配置意图及临时浏览的迟到回调不得写入，过期 revision 以 `CONFIG_STALE` 拒绝

#### Scenario: 重取后磁盘配置无法发布

- **WHEN** 显式重取取得独占锁，但磁盘配置无法读取、损坏或版本未知
- **THEN** 释放本次取得的锁，保持常规配置写入禁用并显示相应的 `CONFIG_READ_FAILED`、`CONFIG_CORRUPT` 或 `CONFIG_VERSION_UNSUPPORTED`，不发布可写状态，不修改原文件或自动重建

#### Scenario: 启动读取损坏配置或未知版本

- **WHEN** 实例启动时读到损坏配置或未知版本，包含与另一实例持锁同时发生的情况
- **THEN** 报告 `CONFIG_CORRUPT` 或 `CONFIG_VERSION_UNSUPPORTED`，保持常规写入关闭，释放本次启动取得的锁，保留原字节；用户确认重建后通过同一锁仲裁

#### Scenario: 备份重建与其他实例争用

- **WHEN** 用户确认重建且一个实例取得独占锁准备备份损坏配置，另一实例同时尝试重建、重取或修改
- **THEN** 持锁方在锁内复查磁盘并完成备份、替换及状态发布；另一实例收到 `CONFIG_LOCKED`，不会创建额外备份或覆盖结果。锁内复查发现当前配置已有效时保留现有数据并提示无需重建

#### Scenario: 退出时仍有异步意图和写入

- **WHEN** 退出时存在慢采集 / 导航、待处理配置意图和已开始的配置事务
- **THEN** 先阻止新意图并作废旧请求，取消采集和未开始的队列意图；只允许已开始的单个事务完成或明确失败，再释放资源，不得让迟到回调或已取消意图在退出后提交或被标为已保存
