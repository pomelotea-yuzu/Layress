## 1. 使用路径与界面

首次启动保留现有临时浏览入口，并提供“新建项目”：填写名称和起始地址，默认选择桌面视口，也可在首次打开前改选。创建成功后才进入项目；用户不必先提供源码目录。
工具栏显示当前项目、地址与视口摘要；项目选择器提供切换、新建、重命名和起始地址编辑。设置在可信工具层内按需展开，不新增顶层窗口。取消编辑不改当前页面或落盘配置。
现有工具层 CSS 视口只有 64px 的根因仍未定位，不能直接往第三行塞项目表单。独立前置任务 0.1 先验证工具层铺满工作区、被测层等尺寸移出可视区：记录工具层 `innerWidth/innerHeight` 与工作区期望值、表单全部控件可见、键盘焦点、实际页面尺寸及状态栏层级。通过前不展开完整项目 UI，配置模型可独立设计。
退路是在同一窗口先修正工具层原生 bounds / CSS 布局，提供实际可容纳表单的可信工作区；仍须保留被测实际尺寸、底部状态栏与权限隔离。若平移方案失败，记录失败与修订后的布局再重跑 0.1；两条路径均不可行时标记依赖 UI 的任务受阻，不用第三行隐藏表单、第二顶层窗口或假通过继续。

编辑与采集预览由显式模式仲裁，禁止靠两个布尔值叠加推断布局：

| 当前模式 / 动作 | 行为与返回目标 |
|---|---|
| 实时页面打开设置 | 记住 `returnTo=live`，移出被测层但不改尺寸或重建；取消 / 关闭回实时页面 |
| 静态预览打开设置 | 记住 `returnTo=preview`、采集 ID、标记、展示比例及页面代号；暂隐预览，取消 / 无现场变化的编辑关闭后恢复同一预览 |
| 编辑中点击采集或收到采集命令 | 入口禁用，可信命令同样拒绝并在状态栏说明；不开始快照、不修改原预览、不暗中关闭编辑 |
| 采集进行中打开设置 | 拒绝打开并提示先完成或取消采集；不会叠出第三种状态 |
| 编辑保存导致项目 / 地址 / 视口变化 | 按对应切换 / 失效规则处理；旧预览保留为旧产物，关闭后回新实时页面，提示原现场已失效，不挂回新项目 |

编辑期间非用户引起的导航使保存的返回上下文过期时，同样回实时页并说明旧预览失效。重命名等不改变现场的提交可以恢复原预览。所有路径都验证普通预览 / 编辑返回不重建原会话；仅明确确认的跨项目切换按 §4 重建。
切换前清楚提示“将重新打开目标项目，当前页面未保存的输入和弹窗不会恢复”；首版每次切换均可取消确认。选中同一个项目不触发无意义重载。
正常启动加载最近活动项目，先设置其视口，再尝试打开最近完成加载的地址；该字段为空时使用起始地址。加载失败显示可重试目标，保留项目配置；不自动改回起始地址冒充恢复成功。
这会正常加载网页及其脚本，不重放点击、输入或表单提交，也不自动启动开发服务。配置恢复提示明确列出业务状态未恢复，不能声称启动没有任何网络请求。
临时浏览不隐式建项目或记录内嵌样例服务的随机端口；项目之外沿用现有行为，界面明确显示“临时浏览，配置未记忆”。

## 2. 配置模型与归属

Rust 层是配置的唯一读写者。前端发送业务意图并渲染返回的已保存状态，不直接读写文件或另存 localStorage。模型、校验和存储与 Tauri 命令 / 页面组件分开，放在现有 `apps/desktop/src-tauri/src/` 内；未来 CLI 可复用同一模型，包提取留出现实际复用时处理。

文件：`<data-root>/config/projects.json`。首次没有文件表示空项目集，不是损坏；首次创建项目时才写入。建议字段如下，实施时保持同一 schema，变更须同步规格与证据：

| 层级 | 字段 | 规则 |
|---|---|---|
| 根 | `schema` | 固定 `layress.project-config/v1` |
| 根 | `revision` | 非负整数，每次成功提交递增，拒绝过期写入 |
| 根 | `activeProjectId` | 项目标识或 null；非空时必须引用现存项目 |
| 根 | `projects` | 项目数组；稳定随机 ID 唯一，名称不作主键 |
| 项目 | `id`, `name` | ID 创建后不变；名称去首尾空白后 1–80 个 Unicode 字符；同名允许，以 ID 区分 |
| 项目 | `startUrl`, `lastLoadedUrl` | 起始地址必填；最近地址可为 null；都只接受既有校验允许的 HTTP(S) URL |
| 项目 | `viewport` | `presetId` 为 `desktop` / `tablet` / `phone` / `custom`；`width` / `height` 为 16–4096 CSS px 的有限整数 |

`lastLoadedUrl` 指本轮可归属的主文档完成加载实际 URL，不代表 HTTP 2xx、登录成功或业务成功。任务 2.3 必须先用可控重定向夹具同时核对 `payload.url()`、WebView 当前 URL 与已知最终端点，确认平台回调的实际含义；不能直接假定 `payload.url()` 就是最终地址。可靠性成立后才接记忆逻辑；无法核对或归属时保留旧值、明确诊断并单列未覆盖项。无效输入、预检失败、导航错误、取消与过期回调不更新它。
本增量记忆显式打开 / 刷新及主文档导航完成事件；WKWebView 若不为 SPA 的 history / hash 变化发主文档加载回调，不承诺记住这些变化。界面说明这一限制，不把地址栏草稿当事实。扩展路由观测须另行核对可靠 API。
编辑 `startUrl` 不导航、不覆盖 `lastLoadedUrl`；提供“打开起始地址”动作，成功加载后自然更新最近地址。
原图与 `layress.capture/v1` 继续由采集模块管理，配置变更不改旧文件；项目 ID 与后续反馈 / 现场关联留反馈 change 设计。

## 3. 视口预设与横竖屏

| 预设 | 初始宽 × 高（CSS px） | 显示名称 |
|---|---|---|
| `desktop` | 1280 × 800 | 桌面视口 |
| `tablet` | 768 × 1024 | 平板视口 |
| `phone` | 390 × 844 | 手机视口 |

这些是通用尺寸，均不是某型号设备或真机结果。界面显示系统 WebView 引擎及实际测量值，并注明未启用 DPR / UA / 触摸 / 软键盘等手机模拟；本 change 不额外引入这些模拟。
旋转交换宽高并保留预设身份；方形尺寸旋转无变化。手改任一宽高改为 `custom`；恢复使用已存的确切宽高，不按新版本预设默认值重新计算。非法值不改已应用或已保存状态。
项目视口使用固定宽高，不持久化“跟随窗口”。工具面板和窗口变化只改变可见区域，放不下时保留实际尺寸、允许现有平移 / 滚动并提示；不靠缩小 WebView bounds 伪装缩放，也不在本 change 引入真实页面缩放。
应用尺寸、展示比例和截图像素不能互相代替。每次采集仍记录当次实测条件，改项目默认配置不修改旧采集元数据。

## 4. 切换、导航与迟到结果

保留单活动页面。确认切换后，先持久提交目标活动项目，再取消在途采集、退出旧静态预览，停止旧导航并销毁旧项目被测 WebView；用目标视口创建新的隔离、非持久被测 WebView 后导航。这样项目切换的会话丢失是明确行为，不冒充项目独立会话库。
旧图仍可作为旧产物保存在磁盘，但不作为目标项目当前图显示。普通预览进入 / 退出仍保留同一个页面会话，不受本次跨项目切换重建规则影响。
在宿主内部维护 `projectId + activationGeneration + navigationGeneration`。每次切换递增激活代号，旧 WebView 回调闭包绑定创建时的项目 / 激活代号，不能在回调到达时只读“当前项目”决定归属。异步可达性预检与写入请求也携带这些身份；过期请求在导航 / 提交前拒绝。
不能仅以 URL 相等证明新旧请求相同。对同一 WebView 内连续导航，主文档完成事件还需与当前导航代号和实际 URL 核对；平台无法可靠归属时跳过该次地址记忆、明确诊断，不能猜造成功。实现中用可控延迟夹具验证同 URL 重试和重定向。
若使用唯一页面标签，任务 3.2 先列完整影响清单：`PAGE_LABEL` 与 `get_webview` 查询、创建 / 销毁 / 导航、`sync_page_frame`、`emit_viewport` / 实测回调、`current_viewport`、布局 / 平移、快照与采集身份、状态查询、退出清理、状态栏 reparent 以及 `capabilities/` 和其他按 windows / webviews 匹配的授权。使用宿主维护的活动视图句柄 / 标签集中解析，不能只替换几个查询。
可信命令仍只给工具层；所有动态被测标签均为零 capability，不新增通配权限。新视图创建后按 I17 把底部状态栏提回顶层。项目 ID 不成为文件路径或原生命令权限来源。
目标页面不可达时，活动项目及其已存配置仍为目标项目；旧页面不得继续作为该项目画面。视口应用或 WebView 创建失败时显示不可操作的错误 / 重试状态，不把旧页挂到新项目下。
跨项目切换持久提交失败则不开始切换，当前项目和页面保留。导航 / 视口已在当前项目生效后若配置写入失败，保留实际运行条件，明确“当前已应用，未保存；重启后可能恢复旧配置”，允许重试，禁止伪报已记忆。

## 5. 数据根与安全写入

复用既有优先级 `--data-dir` > `LAYRESS_DATA_DIR` > 可执行文件旁 `.layress/`，实际绝对路径和可写状态持续可取得。有效来源无论是命令行还是环境变量，显式相对路径均在**解析层**以 `DATA_ROOT_RELATIVE_UNSUPPORTED` 拒绝，提示改用绝对路径；不对已被高优先级覆盖的值单独报错。默认根仍按可执行文件位置解析。这修改既有 `desktop-page-host` 行为，见其 MODIFIED delta；实现后同步 app README / I13 并销账 debt，当前不提前改写主规格或宣称源码已拒绝。
启动解析失败时没有 `DataRoot`，必须将结构化的错误码、来源、请求值和中文提示独立保存到宿主启动状态。`page_state` 总是返回该错误，不以 `if (dataRoot)` 守住；工具层先订阅事件，再读取完整状态，在底部状态栏就绪后补发红条，优先级高于普通“已启动”提示。窗口保留用于显示原因和临时浏览，但配置持久化与采集被禁用，不创建替代根。E05 / E07 必须在两个来源的相对路径下验证**重启后红条可见**。
可写检查失败则已取得绝对根，显示该根、不可写状态与原因，采集 / 持久化同样禁用。这与解析失败是两条独立验证路径，早期 stderr 或可能丢失的事件都不能代替 GUI 可见结果。
项目 JSON、同目录写入临时文件和 `projects.lock` 都在该数据根内；项目地址、项目名不能影响配置路径。不得使用 Tauri 默认用户配置目录、`os.tmpdir()` 或其他系统用户目录兜底。产品不写根外配置，测试夹具放仓库忽略的 `artifacts/` / `.layress/`。
启动时取得配置文件的独占写锁，采用随持有进程退出而由系统释放的文件锁；实施时核对当前 Rust 工具链接口。拿不到锁的第二实例只读展示已读配置，明确“另一实例占用，只读”；创建 / 编辑 / 重建 / 项目切换均禁用，可信命令绕过按钮调用时也以 `CONFIG_LOCKED` 拒绝。可加载启动时已读的活动项目并临时浏览，但不更新最近地址或视口记忆；不冒充多实例合并。内存模型和 revision 不跨实例共享。释放锁后需显式重试取得锁并重新读取最新 revision，再启用写入。
进程内只有一个串行写队列；写入前核对 revision、完整字段和引用。新内容写入同目录唯一临时文件，完整写入并同步后原子替换正式文件，成功后再发布新 revision 和“已保存”。替换失败保留原文件；临时文件可在持锁且确认属于本配置写入时清理，不扫描删除用户其他文件。
退出顺序固定：①设置 `quitting`，作废激活 / 导航 / 采集代号并禁止新配置意图入队；②停止导航、取消在途采集，丢弃尚未开始的写队列意图并标取消，迟到回调不得再提交；③只等待已开始的单个配置事务完整提交或明确失败，其结果才可称已保存；④释放视图、锁与本次资源。取消采集不能产生新的地址记忆写入；退出前已完成的有效事务不倒退。测试核对退出前后 revision / 文件字节、队列取消结果及没有退出后新提交，不依赖仅在退出时一次保存。
中断恢复须得到旧完整版本或新完整版本，不允许截断 JSON；断电耐久性和未实测平台的原子替换限制单列，不虚构跨平台保证。

## 6. 损坏、版本和错误表达

根对象及所有项目先整体校验，再作为可编辑配置发布。JSON 损坏、重复 ID、无效 URL / 尺寸、悬空活动 ID 或未知 schema 均阻止自动写入；不取部分字段凑默认值回写。原文件字节保留，当前进入明确的临时浏览 / 配置错误状态。
用户可取消错误处理，也可主动选择“备份并重建项目配置”。必须说明会清空项目记忆、保留截图；确认后在 `config/` 内按唯一名称完整备份原始字节，备份成功才允许原子提交空配置；任一步失败保留原文件，不启用新配置。未知版本同样不自动降级；用户显式重建也保留原始备份。
备份名为 `projects.backup.<unix-ms>.<随机后缀>.json`，用排他创建避免覆盖；备份不作为活动配置自动读取、回退或参与下一次重建的输入，唯一活动文件仍为 `projects.json`。本能力创建的备份最多保留 10 份，达到上限时拒绝新重建（`CONFIG_WRITE_FAILED`，原因注明备份已满），展示目录并提示用户自行清理后重试；不自动淘汰任何备份或用户文件。备份成功但空配置提交失败时保留这份备份并计入上限。E06 核对字节、命名、计数、上限拒绝及无自动读取 / 删除。
新增结果按稳定代码区分：`CONFIG_INVALID_INPUT`、`CONFIG_READ_FAILED`、`CONFIG_CORRUPT`、`CONFIG_VERSION_UNSUPPORTED`、`CONFIG_WRITE_FAILED`、`CONFIG_LOCKED`、`CONFIG_STALE`、`DATA_ROOT_RELATIVE_UNSUPPORTED`；由 Rust 返回结构化错误，前端映射中文。此为内部应用接口，不宣称已发布 CLI 协议。
所有进行中 / 成功 / 拒绝 / 失败经 `showStatusBar` → `status_bar_set`，项目摘要可持续显示“未保存 / 只读”等状态；不得依赖已知被裁掉的工具条第三行传达结论（I15）。每次工具层前端改动递增 `BUILD_TAG` 并同步 `index.html` 的 `data-build`，复验记录窗口实际徽标值，不能仅检查两个旧值相等。
任务 4.1 同轮升级版本门禁为与工具层前端源码集合的内容指纹绑定：按确定文件清单及规范化规则计算，排除存放徽标 / 指纹的自引用字段；仅改业务源码而保留旧徽标 / 指纹必须失败，更新版本与指纹后才通过。新增工具层模块须纳入清单；这项尚未实现，不把既有“相等”断言描述成已能检测所有源码变更。

## 7. 实施落点、验证与取舍

预计触及可信工具界面的 `apps/desktop/src/main.ts` / `index.html`、Rust `src/lib.rs` 与 `capture.rs` 数据根入口，并在现有源码目录增加配置模型、文件存储与状态编排模块。复用当前 serde / URL 等依赖，不为配置记忆先加数据库、UI 框架、Node 运行时或空 workspace 包；若确需新依赖，实施前登记版本、许可与缓存落点。
JSON 单文件适合当前小规模项目配置，原子替换比分散文件减少部分成功；代价是串行整体写入和当前只允许一个写实例。localStorage 依赖 WebView 的用户目录 / 会话，难统一后续 CLI；SQLite 在本增量没有需要它的查询或记录规模，均不选。
