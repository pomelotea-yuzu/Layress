## Why

首个 [add-tauri-page-host](../archive/2026-11-14-add-tauri-page-host/proposal.md) 已完成页面承载、基础视口、真实采集与原地预览，但项目、地址和设备配置还没有持久记忆。每次重启或换项目都要重新准备条件。
本增量承接[阶段 1 计划](../../../docs/product/2026-11-10-stage-one-plan.md)的第二步，让用户在两个项目之间切换、关闭重开后继续使用各自的地址和视口，为后续反馈归属和按条件打开打基础。

## What Changes

- 创建和重命名项目，编辑起始 HTTP(S) 地址；用稳定项目标识保存最近完成加载的实际地址，支持切换项目。
- 提供通用桌面 / 平板 / 手机**视口预设**、自定义宽高与横竖屏，按项目保存上次配置。
- 启动恢复最近项目及其地址、视口，先应用视口再导航；服务离线时保留记录并支持重试。
- 将版本化配置集中保存在既有数据根，由 Rust 负责校验、串行写入和原子替换；保存失败、文件损坏、未知版本与多实例冲突均明确处理。
- 在已有单窗口内提供紧凑项目入口与设置面板，结果类反馈沿用底部独立状态栏；实际视口不随工具布局静默改变。

## Capabilities

### New Capabilities

- `project-device-profiles`：项目身份、地址记忆、视口选择与恢复、配置持久化和异常保护，见[规格增量](specs/project-device-profiles/spec.md)。

### Modified Capabilities

- `desktop-page-host`：修订「便携数据根与可写检查」，明确有效来源为 `--data-dir` 或 `LAYRESS_DATA_DIR` 时均拒绝相对路径，并补启动解析失败的状态栏反馈。见 [MODIFIED 规格增量](specs/desktop-page-host/spec.md)；当前主规格保持已交付口径，实施验证完成、归档时才合入修订。

## Impact

- 预计修改 `apps/desktop/` 的可信工具界面、Rust 状态与导航编排，在现有源码目录内新增配置模型 / 存储模块；本轮不创建产品模块或共用空包。
- 使用数据根下 `config/projects.json`（`layress.project-config/v1`），锁与写入临时文件也位于该根；不使用 WebView localStorage、系统用户配置目录或第二套数据根。
- 修改共享数据根解析入口与启动错误展示，影响项目配置及既有采集；实施后同步 app README、I13 说明并销账相对路径欠账。D30 的真实 WebView 写盘观测范围不变。
- 现有 `captures/` 文件及 `layress.capture/v1` 不迁移、不重写；本轮不为历史截图补造项目归属。
- 配置逻辑、写入失败与竞态行为的必要测试进入现有 `check-repo.mjs` 公共链。首轮实机范围仍为 macOS arm64；其他平台未实测单列。

## Scope

本 change 包含项目创建 / 重命名 / 起始地址编辑 / 切换、最近地址记忆、通用视口预设、自定义尺寸、旋转、重启恢复和配置错误恢复。
项目删除、源码目录绑定、多标签、项目独立登录会话、完整手机模拟、真实页面缩放、反馈 / 补拍、CLI / MCP 与跨平台发行留后续。保留现有静态预览缩放；本增量以平移 / 裁切和明确提示处理放不下的真实视口。
这是按阶段计划正文“缩放或平移”选择平移；真实页面展示缩放已登记到 debt，是否另立增量由用户后续定夺。
配置恢复不承诺登录、输入、弹窗、滚动或业务流程恢复；切换项目会重新打开页面，并在界面说明临时页面状态会丢失。
真实 WebView 写盘观测与打包产物运行验证继续归 D30 的发行轮，不以本次配置落点正确宣称“便携通过”。

## Completion

两个项目分别保存桌面与手机视口及最近地址；切换、退出重开后各自恢复。调整窗口或展开设置不改变选定视口；旧项目的迟到结果不写入新项目；无效输入、离线页面、不可写目录、损坏 / 未知版本配置、并发实例均有可核对的失败结果，旧文件和旧截图保持可用。
