# project-device-profiles Specification

## Purpose
在既有单窗口工作台的数据根内持久化项目与设备配置：以稳定 ID 创建 / 重命名项目、编辑起始地址、按项目记忆最近完成加载的实际地址与视口（通用预设 / 自定义 / 旋转），支持跨项目切换与重启恢复；配置由 Rust 校验并以 `layress.project-config/v1` 版本化原子写入，写入失败、文件损坏、未知版本与并发实例均有明确结果。该能力不涵盖反馈任务管理、源码目录绑定、多标签与完整手机模拟；SPA history / hash 追踪为首版明示限制。首轮验证平台为 macOS arm64，其他平台接入前不得宣称已支持。

## Requirements


### Requirement: 稳定项目身份与基础编辑

系统 MUST 支持创建、重命名项目和编辑起始 HTTP(S) 地址，以稳定且唯一的 ID 关联配置；名称不得用作存储主键。取消或无效编辑不得改变已保存配置。未创建项目时 MUST 保留明确标识的临时浏览入口，不自动持久化样例或临时浏览配置。

#### Scenario: 创建并重命名项目

- **WHEN** 用户创建两个项目并重命名其中一个
- **THEN** 两者有不同且不随改名改变的 ID，起始地址和视口分别归属原项目

#### Scenario: 编辑无效或取消

- **WHEN** 用户提交空名称、无效 / 非 HTTP(S) 起始地址，或取消编辑
- **THEN** 无效输入有明确错误，取消不提交，已保存配置和当前页面均不改变

#### Scenario: 没有项目记录

- **WHEN** 首次启动且项目配置文件不存在
- **THEN** 系统显示空项目状态，允许新建或临时浏览，不将不存在的配置误报损坏，也不自动记忆内嵌样例地址

### Requirement: 最近地址的事实记忆

系统 MUST 将可归属当前项目的主文档完成加载实际 HTTP(S) 地址与起始地址、地址输入草稿区分，拒绝用失败 / 取消 / 过期结果更新最近地址；记忆地址不等于验证 HTTP 状态或业务成功。首版 MUST 明示仅覆盖主文档加载，不承诺未观测的 SPA history / hash 变化。

#### Scenario: 导航完成与重定向

- **WHEN** 当前项目的导航正常完成，包含可归属的重定向完成
- **THEN** 最近地址记录最终实际 URL，起始地址独立保留，系统不声称业务已通过

#### Scenario: 导航失败或仍是输入草稿

- **WHEN** 用户只编辑地址草稿，或导航因预检失败 / 错误 / 取消未完成
- **THEN** 已记忆的最近地址不变；失败时明确区分目标地址与旧页面实际地址

### Requirement: 可核对的视口选择与旋转

系统 MUST 提供桌面 1280×800、平板 768×1024、手机 390×844 CSS px 通用视口预设，以及 16–4096 CSS px 有限整数的自定义宽高与宽高交换；按项目保存确切尺寸和预设身份。系统 MUST 区分实际视口、DPR、截图像素、展示比例和系统 WebView 引擎，标明未启用的设备模拟项，不将预设宣称为完整手机模拟或真机验证。

#### Scenario: 选择预设后旋转和自定义

- **WHEN** 用户选择手机视口、旋转，再手动编辑一个宽高值
- **THEN** 旋转得到 844×390 并保留手机预设身份，手动编辑后变为自定义；合法尺寸可核对并按项目保存

#### Scenario: 无效尺寸与方形旋转

- **WHEN** 输入非有限值、非整数或超范围值，或旋转方形视口
- **THEN** 无效输入被拒绝且不改已应用 / 已保存尺寸；方形旋转维持原尺寸

### Requirement: 按项目切换与重启恢复

系统 MUST 独立记忆各项目视口和地址及最近活动项目，切换或重启时先恢复确切视口再尝试打开最近完成加载地址，最近地址为空时使用起始地址。切换 MUST 可取消并说明将重新打开页面及丢失临时业务状态；不得暗示登录、表单、弹窗、滚动或业务操作已自动恢复。

#### Scenario: 两项目往返与重新启动

- **WHEN** 两项目分别保存桌面和手机配置及不同最近地址，用户往返切换并正常退出重开
- **THEN** 各自恢复已保存的地址和确切尺寸，启动恢复最近活动项目，其他项目配置不被覆盖；选中已活动项目不无故重载

#### Scenario: 目标离线或打开失败

- **WHEN** 恢复的项目服务不可达，或其 WebView 创建 / 视口应用失败
- **THEN** 显示目标项目的失败和重试入口，保留其地址与配置，不把旧项目画面或偷偷改用起始地址当成恢复成功

#### Scenario: 取消切换与单独编辑起始地址

- **WHEN** 用户取消项目切换，或仅保存新的起始地址
- **THEN** 取消保持当前项目和页面；仅编辑起始地址不导航，也不覆盖最近地址，用户可显式打开起始地址

### Requirement: 项目归属与迟到结果隔离

系统 MUST 将异步导航、预检、配置写入和采集结果绑定项目身份及对应操作代号；切换项目作废旧请求和旧预览，拒绝迟到结果写入新项目或成为新项目当前现场。被测页面 MUST 继续保持原生权限隔离，新建 WebView 不得遮挡底部状态栏。

#### Scenario: 旧项目结果在切换后到达

- **WHEN** A 的慢预检 / 导航 / 采集未完成便切到 B，随后 A 的结果返回
- **THEN** A 的结果不会导航 B、覆盖 B 的最近地址 / 视口或成为 B 的当前图片，已有截图文件不被重写

#### Scenario: 同地址重试或过期写请求

- **WHEN** 连续请求使用相同 URL，或旧 revision 的配置提交在新提交后到达
- **THEN** 以项目和操作身份判断归属，过期写入被拒绝；无法可靠归属的加载不更新记忆，不仅凭 URL 相等接受旧结果

#### Scenario: 切换后核对权限与状态栏

- **WHEN** 切换项目创建新的被测 WebView 并在较小窗口触发拒绝或失败
- **THEN** 被测页仍不能调用工具原生命令，底部状态栏结果可见且不被页面覆盖

### Requirement: 工具布局不改变选定视口

系统 MUST 在调整窗口、打开 / 关闭项目设置和返回静态预览时保持选定的实际页面宽高；显示区域不足时明确提示并提供不改变实际视口的查看方式，不能静默缩小宽高却继续显示原配置。

#### Scenario: 小窗口和设置面板

- **WHEN** 已选择固定视口后缩小应用窗口或展开 / 关闭项目设置
- **THEN** 页面实际视口和后续采集条件仍对应所选尺寸，工具入口和状态栏可使用，显示限制明确可见

#### Scenario: 编辑与静态预览仲裁

- **WHEN** 用户从预览进入设置、在编辑中请求采集，再取消或完成不改变现场的编辑
- **THEN** 编辑期间采集被拒绝且状态栏说明原因，关闭后恢复同一采集 ID / 标记 / 展示比例的预览，原 WebView 会话不重建；若编辑或页面导航使现场过期则回实时页并明确失效，不能恢复为新项目当前现场

### Requirement: 便携数据根内的版本化持久化

系统 MUST 在既有可见数据根内读写 `config/projects.json`，使用 `layress.project-config/v1`、revision 与稳定项目 ID；锁和临时文件也必须在该根内，不使用系统用户目录或 WebView localStorage 兜底。有效来源为 `--data-dir` 或 `LAYRESS_DATA_DIR` 的显式相对根 MUST 在解析层明确拒绝，不随启动工作目录变化解析。配置更新不得修改旧截图和采集元数据。

#### Scenario: 默认根与自定义绝对根

- **WHEN** 分别使用默认根和用户显式指定的可写绝对根保存、退出和重开
- **THEN** 项目配置从显示的实际数据根恢复，全部配置写入附属文件位于该根内，旧采集元数据保持原值

#### Scenario: 不可写根或相对根

- **WHEN** 数据根不可写，或有效的命令行 / 环境变量来源被显式指定为相对路径
- **THEN** 不可写显示已解析根及原因；相对路径以 `DATA_ROOT_RELATIVE_UNSUPPORTED` 在解析层拒绝且即使根不存在也在状态栏就绪后显示红条和绝对路径提示，两种失败都禁用配置持久化 / 采集，不创建替代根，不显示已保存

### Requirement: 提交失败与并发保护

系统 MUST 串行验证并原子提交配置，仅在正式文件提交成功后发布已保存状态；写入失败或中断不得截断最后完整配置。第二实例无配置写锁时 MUST 明示只读并拒绝写入；过期 revision 不得覆盖新配置。

#### Scenario: 写入或替换失败

- **WHEN** 在写临时文件或替换正式文件时发生错误
- **THEN** 原正式文件字节保留，显示保存失败；跨项目切换不开始，当前项目内已生效但未保存的条件明确标识并可重试

#### Scenario: 配置提交中断后重新启动

- **WHEN** 在临时文件写入和原子替换的不同阶段中断进程后重新启动
- **THEN** 读取到旧完整版本或新完整版本，不能把半份 JSON 当有效配置，未提交意图不被宣称已保存

#### Scenario: 第二实例争用配置

- **WHEN** 同一数据根已被另一存活实例持有配置写锁
- **THEN** 第二实例以明确的只读状态展示已读配置，创建 / 编辑 / 重建 / 项目切换及其命令均以 `CONFIG_LOCKED` 拒绝，可临时浏览但不记忆；持锁进程退出后锁由系统释放，第二实例需显式重取锁并重读最新 revision 才能写入

#### Scenario: 退出时仍有异步意图和写入

- **WHEN** 退出时存在慢采集 / 导航、待处理配置意图和已开始的配置事务
- **THEN** 先阻止新意图并作废旧请求，取消采集和未开始的队列意图；只允许已开始的单个事务完成或明确失败，再释放资源，不得让迟到回调或已取消意图在退出后提交或被标为已保存

### Requirement: 损坏与未知版本的显式恢复

系统 MUST 在发布可编辑配置前验证整体结构、项目唯一性、引用、URL、尺寸和 schema。损坏或未知版本 MUST 保留原始字节并禁止自动覆写，提供明确错误及临时浏览；只有用户主动确认且原始字节备份成功后才能重建空配置，重建不得删除已有截图。

#### Scenario: 损坏或高版本文件

- **WHEN** 启动读取截断 JSON、重复项目 ID、悬空引用、非法字段或未知 schema
- **THEN** 损坏返回 `CONFIG_CORRUPT`，未知 schema 返回 `CONFIG_VERSION_UNSUPPORTED`，原文件不变，不以默认项目覆盖，也不发布猜造的部分配置

#### Scenario: 确认重建及备份失败

- **WHEN** 用户取消恢复，或确认备份重建但备份失败
- **THEN** 原配置字节与截图保持原样，写入继续禁用；只有确认且完整备份成功、空配置提交成功后才启用新配置

#### Scenario: 备份保留与达到上限

- **WHEN** 重建产生备份，或本能力命名的备份已达到 10 份后用户再次请求重建
- **THEN** 备份以含时间与随机后缀的唯一名称保留原始字节，不自动作为活动配置读取或删除；达到上限时以 `CONFIG_WRITE_FAILED` 拒绝新重建并提示用户自行清理，原配置与已有备份不变
